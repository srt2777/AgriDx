# 知识快照与目录版本一致性（3.11.1）

## 实际问题

共享知识正文、目录和统计已经由snapshot统一加载；但目录HTTP路由仍单独读取kb-version.json，使用模块级永久缓存。成功重载知识快照后该缓存不会更新，可能返回“新知识数据+旧版本号”。该隐藏文件依赖也越过了路由工厂注入的getCatalog。开发预览快照未包含版本记录，导致同一资料的预览目录没有生产目录的kbVersion。

## 调整后的职责

- snapshot.ts在构建新数据代际时读取一次可选版本元数据，连同只读目录一起发布；只有其余知识、层级与通用框架校验全部通过，才切换current。
- KnowledgeSnapshot.kbVersion与其getCatalog()结果属于同一代际；未筛选目录继续复用同一只读对象，筛选结果也带同一版本。
- 目录HTTP只负责筛选校验、调用注入的getCatalog、序列化及错误状态，不读取知识文件、不保存模块级版本缓存。两个独立路由可使用各自注入的数据和版次。
- 开发预览生成器把存在的公开kb-version.json与已索引资料一起打包，浏览器使用同一快照加载代码；不添加密钥、原始PDF或生产接口代理。

## 兼容性与边界

保留目录kbVersion为字符串或null的HTTP约定，原字段和筛选规则不变。版本文件缺失、JSON损坏或字段非字符串时仍为null，不阻断知识使用；沿用既有语义，不新增运行时哈希审计。版本内容哈希仍由现有离线verify校验。

重载失败保留上一快照及其版本、检索缓存、统计和型号识别。成功重载后，新调用读取新版；仍持有旧快照的消费者继续看到旧数据与旧版本，不能修改冻结结果。重载是同步构建与整体替换，并不等于自动监听文件或跨进程同步。

本批不修改知识正文、条目、来源、角色、适用范围或知识库版次。项目仅增加一个maintenance补丁，同批修正不重复升版。

## 回归验证

- 版本记录每代只读一次，目录HTTP反复读取不增加文件访问。
- 独立HTTP路由实例遵守注入版本，不读取全局版本文件。
- 成功重载同步切换版本，旧快照和来源字段不被污染。
- 层级损坏时不会切换数据或版本，检索与统计保持原值。
- 缺失、坏JSON和非字符串元数据保持null兼容。
- 既有开发浏览器构建与服务端目录对比继续覆盖完整品牌、型号、组件、部件和分页，同时明确验证kbVersion。
