# 自动版本更新规则

当前有效上限为 **4.x.x**；可执行策略以根目录 `version-policy.json` 为准，变更上限须引用用户明确授权。

用户于 2026年10月13日确认：知识库内容更新统一增加补丁号，不再因数量大或覆盖新机型自动增加次版本。版本使用三个整数，不使用小数：3.4.8 的下一补丁是 3.4.9。

| 更新类型 | 命令类型 | 递进方式 |
| --- | --- | --- |
| 新增、修正知识条目、手册、来源、索引、覆盖品牌与机型 | knowledge | X.Y.Z → X.Y.(Z+1) |
| 修复已有功能 | fix | 补丁 |
| 兼容重构、性能、样式、文案与维护 | maintenance | 补丁 |
| 4.x 一般功能改进 | feature | 4.Y.Z → 4.Y.(Z+1) |
| 较大阶段性发布 | 人工协调 | 明确发布范围后协调次版本 |
| 不兼容接口、数据或运行方式变化 | breaking | (X+1).0.0 |

当前阶段按用户2026-10-25在渐进优化聊天中的最新明确答复“授权沿4.x主线继续”使用 **4.x.x 上限**：保留已合入的4.0.0装备陈列，一般功能与维护按补丁递进，阶段性发布再协调次版本；5.0.0及更高主版本仍需用户明确授权。此前3.x.x及4.0.0封顶等规则保留为历史记录。版本继续使用X.Y.Z三个安全整数，不按字符串或小数比较，同批修正不重复升版；不直接跳号；保留真实更新类型。

## 执行方式

完成一批授权改动后，在任务分支执行：

```powershell
npm.cmd run version:update -- --kind knowledge --batch kb-20261013-a --summary "扩充本批农机资料" --dry-run
npm.cmd run version:update -- --kind knowledge --batch kb-20261013-a --summary "扩充本批农机资料"
npm.cmd run check:version
```

脚本自动计算版本，同步 package.json、锁文件两处根版本、README 当前版本和 CHANGELOG 最新条目，同时保存 version-batches.json。依赖版本、手册版次和历史记录不替换。日期使用上海时区。

每批使用唯一 ID；同批修正重复运行沿用该版本，不重复增加日志。旧批次不能在后续发布中复用。重复运行不会自动替换说明，需在该版 CHANGELOG 中补充最终交付与真实验证结果。同批多种改动选最高级别，不把增量相加；知识内容扩充本身始终为 knowledge。

并行分支合入前同步最新 main，协调批次 ID 和版本记录。发生版本冲突时不能简单保留某一方；按共同发布范围重整批次及日志。脚本不猜测文件改动是否破坏兼容，由执行者在 PR 写明所选类型和理由。

## 自动化边界

这是执行者调用的自动计算与同步命令，不是每次 commit 自动升版。AGENTS.md 要求后续任务使用本规则；现有 check:version 与 verify 持续检查版本一致性和上限。脚本不自动提交、推送、合并、建标签、建 Release 或部署。GitHub 保存和现有 main 开发站发布分别沿用原约定。

只需安装 Node 即可运行脚本及专用测试：`node --test tests/version-update.test.mjs`。每次提交补充与改动相关的检查，主线合入前完成项目要求的验证。

## 更新日志格式

版本历史网页直接从 CHANGELOG 构建生成，维护方式见[版本历史记录](version-history.md)。自动升版模板现包括详细改动、知识库变化、兼容性、验证结果、关联 PR、部署记录；执行者填入真实证据，缺失保留“未记录”。同批补充日志不重复升版，部署记录不会自动转换为当前正式站成功状态。

4.x 按用户要求归并编号，旧记录和批次分别保存在 `docs/changelog/4.x-original.md` 与 `docs/changelog/4.x-original-batches.json`；其他历史节不改写。旧编号可能与新编号相同但内容不同，引用时必须附日期和提交。本项目 4.x 自定义编号不严格符合 SemVer 的新增功能升次版本约定。`npm run check:version`（含于 `verify`）检查最新版本的批次 ID 和更新类型，对缺失的验证及部署内容给出警告；`--release` 将内容要求作为门槛。部署状态如实写“未部署”或实际结果。PR 描述按 `.github/pull_request_template.md` 填写。

## 知识库版本

知识库另有独立版本 `kb_version`（`YYYY.MM.N`，与项目 SemVer 分开），记录在 `知识库/整理后的知识库/农用拖拉机知识库/kb-version.json`，附内容哈希与计数。知识条目、来源、层级、通识索引或整理 Markdown 变化时，运行 `node scripts/kb-version.mjs --bump`；`verify` 发现哈希变了而版本未升会失败。项目补丁号仍按上表照常递增。

## 补充工具

- `npm run check:version -- --release` 要求最新版本的详细改动和验证结果有实际内容，关联 PR 可以写未记录，部署记录需写未部署或实际结果。日常检查对缺失内容给出警告。
- `npm run version:log -- --batch ID --verified "实际验证" --pr 123 --deploy "未部署"` 补充指定批次；已有内容需要 `--replace` 才会覆盖。
- `npm run version:rebase -- --dry-run` 在更新 origin/main 后预演单个新批次的版本协调；历史冲突、多个本分支批次或无法安全合并的文件会拒绝并要求人工处理。去掉 `--dry-run` 才写入；不执行 git rebase、提交或部署。
- `npm run version:verify-live -- --url https://站点` 核对版本文件、健康接口、网页提交、GitHub main 与工作流；缺项或不一致均标记未验证。私有站点需自行解决访问，工具不获取或保存用户凭据。
