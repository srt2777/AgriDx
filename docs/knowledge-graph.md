# 知识库分类关系图

入口：`/#/knowledge?view=graph`，知识页选择“知识图谱”。3.13.5起弃用球形知识星系及WebGL渲染器，改用固定分层分类浏览。

## 2026-10-31：归档与学习主题分开浏览

- 保留来源归档图谱的品牌、机型、系统和零件归属，增加资料类型与已标注角色筛选；两种条件在节点上分别按各自汇总判断，原文列表再对同一条目同时筛选，避免把不同条目的属性误说成同一证据。
- 增加“通识与术语图谱”：按既有资料类别生成2个分类节点、按既有主题生成305个主题节点，连线仅表示主题归属。两类节点分开展示，可搜索主题并进入相应原始条目；图形节点不是新知识或故障因果关系。
- 选中节点时定位到画布中部并暂缓自动运动；返回全图保留视角。图谱使用同一知识快照，源资料、机型适用范围和“千寻位置”展示排除规则未改变。

## 分类依据与顺序

- 节点来自现有 `/api/knowledge/catalog`，按“品牌 → 机型/系列 → 系统/组件 → 零部件 → 原始证据”展开。
- 保持API返回顺序；品牌/机型使用已有目录排序，组件与零件遵循人工维护的 `hierarchy.json` 顺序。界面不按数量、模型猜测、动画位置重新排序。
- 标识包含完整上级路径，同名零件不跨机型合并。搜索显示完整路径，选中后展开对应上级。
- 选择机型后加载已有知识卡，保留原始正文、来源、页码、状态和适用范围；零件未定位时留在组件层。零条目节点明确显示待补资料。
- 通识仍在独立入口；分类边仅表示资料归属，不构造先修依赖、维修步骤、兼容性或故障因果。各层计数不可相加当作独立知识条数。

## 参考项目

参考 [withmarbleapp/os-taxonomy](https://github.com/withmarbleapp/os-taxonomy) 的主题分类、关系与来源分离思路。该仓库为教育微主题及先修关系数据，并非现成图谱UI组件。本项目未导入其课程数据、未复制代码，农机节点与顺序全部取自本地知识库，因此不将其先修图套用于农机维修。

## 交互

四列固定层级，选择上级清除下级，面包屑支持返回；搜索支持跨目录定位，最多显示50个匹配并说明总数。手机横向滑动逐列浏览；节点为原生按钮，支持键盘。证据区提供加载、错误重试、空状态及带机型进入诊断。目录没有内容时不生成占位知识。

旧球形视图及边界粒子效果在3.13.5弃用，历史实现及验证记录保留在Git历史和对应版本日志中。

## 3.13.6：节点连线图谱替换四列主视图

用户明确要求使用os-taxonomy示例的图谱交互。主视图改为深色三维投影节点连线画布：按品牌着色、按真实目录深度分层，支持拖动旋转、缩放、点击节点、祖先路径高亮与分支聚焦。布局保持已有目录同级顺序，不按图形引力随意重排。四列目录仅保留在折叠辅助区，供键盘与无图形浏览。

图形使用Canvas绘制三维坐标的透视投影，按需重绘，不要求WebGL、无自动漫游。并非嵌入Marble教育网站或复制其未公开的界面源代码；数据仍全部来自AgriDx。示例中的教育年龄高度改为目录层级，先修边改为有证据的目录归属，不构造维修先后。

## 3.13.8：球形布局，结构不变

按用户要求仅把节点坐标改为确定性的球面分布，同一目录输入始终产生相同坐标。品牌配色继续继承，节点编号、原始顺序、父子归属、查询参数、关系边及证据选择均不改变。球面位置不再代表分类深度；分类层级仍通过连线、路径和辅助目录查看。保持旋转、缩放、分支聚焦与原文跳转，远近节点按深度绘制并区分透明度，保留新版与经典版各自配色。

## 流动球团与扩散粒子（3.13.9）

球面规则排列改为按节点编号生成的稳定随机立体球团，消除规则条纹。知识节点在有限范围内进行三轴漂移与径向呼吸，整体视角缓慢摆动；外围独立微粒向外扩散、渐隐后循环。粒子只是装饰，没有知识编号，不参与查询或点击命中。节点、原有父子关系与原始证据保持不变。

动画最高约30帧每秒，仅在画布可见且页面位于前台时运行。提供暂停/继续按钮；选中知识节点时冻结流动便于阅读，清除选择后恢复。拖动时冻结流动，保持选点稳定。系统减少动态偏好下默认静止；手机减少装饰粒子数量。恢复时不累加后台时间，轨迹有界，不无限扩散知识节点。保留新旧界面品牌配色。

## 图谱交互与关系聚焦（3.13.10）

缩放工具明确显示“放大/缩小”和实时倍率；支持滚轮锚点缩放、双击放大、双指捏合、键盘加减与“适应画布”。“放大画布”使用独立覆盖层，可按Escape或按钮收起，保留选择并限制键盘焦点在覆盖层内。

拖动旋转、平移和缩放采用同一持久绘图循环，输入更新目标相机后平滑追随，停止拖动带有短暂阻尼。关系聚焦视图中拖动用于平移；全图中Shift拖动平移。减少动态偏好下取消惯性并直接定位。

选中节点自动展开可读的关系图：显示真实祖先链、当前节点和前10个直接下级，节点使用名称卡片和方向箭头；右侧/手机下方列出完整下级与条目数量，可继续追踪或跳到原始证据。超过10项时明确说明画布范围，列表不截断；没有下级时保留叶节点说明。图谱关系仅来自现有目录，不增加故障因果或先修关系。“全图上下文”可回到球团，保留所选关系高亮并弱化无关节点。

## 关系强度（数据层）

`GET /api/knowledge/relations` 从目录所属的同一不可变快照计算关系，并随快照整体替换；开发预览和 Express 使用相同构造函数。千寻位置节点继续只在图谱展示中排除，源知识不删除。`formulaVersion=1.0.0` 表示以下启发式规则；强度不是概率、因果、先修顺序、维修适用性或兼容性。

- **目录归属**：子条目数为零时强度为零；否则为 `min(1, log(1 + 子条目数) / log(1 + 父条目数))`。依据给出父子原始计数，零条目继续表示待补资料。
- **同名部件**：只在不同品牌/机型、相同节点层级且名称完全一致时连接；强度为双方目录归属强度较小值，乘以 `log(1 + 较小条目数) / log(1 + 较大条目数)` 和五种已核对角色计数的加权 Jaccard 交集/并集。无已核对角色时相似度为零；单条强度不超过双方目录归属强度。证据保留名称、双方数量、角色相似度与上限。
- **语义候选**：仅载入 `docs/knowledge-semantic-report.json` 的完整、未阻塞、待审核报告，核对报告快照文件清单摘要及当前索引、正文、来源的 SHA-256；缺失、过期、节选或不匹配时降级并返回原因。条目按已有层级索引映射到目录节点；按节点对和关系类型聚合。强度为关系类型权重乘以 `1 - 1/(1 + 候选数)`，权重依次为 exact_duplicate 0.6、semantic_duplicate 0.55、partial_overlap 0.45、scope_variant 0.35、complementary 0.3、uncertain 0.2；证据记录关系类型、候选数量和编号。规则模式不把字面分数当作向量相似度，也不自动审核候选。

报告在同一快照载入前后各校验一次；开发预览构建时验证并仅打包必要候选编号，不把原始手册放入浏览器。默认响应包含全部关系；可传 `?offset=0&limit=2000` 分页（上限 10000），响应 `page.total` 与 `page.hasMore` 明示范围。分页不改变关系本身，调用者需逐页读取完整图。

本地 2026-10-27 实测 3,984 节点、135,517 边、约 50,084,427 字节未压缩 JSON（无语义报告），构造耗时随设备和缓存变化；跨机型同名边数量高，地形视图必须另行测量和处理，不能把这些数字写成已经达成帧率目标。已有报告示例是旧快照节选，不能作为当前语义结果。
