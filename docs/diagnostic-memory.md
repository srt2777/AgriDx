# 诊断记忆（3.0.2）

智能体的记忆由应用保存和读取，不是模型训练。DeepSeek、Gemini和本地知识答复共用同一份记录。

## 后续参与者：记忆分层与恢复

按[Agent设计指南](agent-development.md)区分当前工作记忆、持久会话/设备记录与后续长期事实召回。已有SQLite保存与历史用户报告匹配不等于已实现自动事实提取、语义Memory Bank或事件唤醒的长任务引擎；独立开发预览仍使用浏览器存储。

扩展记忆时注明归属、设备、来源、时间、核验状态及当前纠正，沿用应用上下文、事务和revision。当前用户纠正优先，历史助手推断、用户检查报告及仿真数据不能变成已验证故障或手册事实。新增事实召回需定义更新、过期、清空/删除和取消后的行为，不把私人记录放进公共快照或GitHub。

后续任务恢复需要单独的任务状态与持久检查点，不能从“对话可恢复”推导“中断工具会自动续跑”。相关PR验证同身份同设备恢复、跨设备隔离、型号纠正、并发冲突及迟到响应；若引入事件驱动流程，再验证重启恢复和重复事件幂等。

## 使用

1. 在诊断工作台展开“诊断记忆”，给设备命名，填写机型、使用小时和维护记录，保存设备档案。首次发送也会自动建立档案和诊断。
2. 对话自动保存。刷新或重新打开同一浏览器会恢复最后一次诊断；也可通过“继续历史诊断”选择其他记录。
3. “本次检查进度”填写已经检查的项目、结果和待检查项，再点击保存。信息标为用户报告，不是实车验证。
4. 同一台设备的新问题可以“新建诊断”；设备档案保留，当前检查进度独立。同一设备其他诊断中与当前症状有文字匹配的用户检查报告会作为历史参考，不能当成本次已完成检查。
5. 另一台车必须选择或新建设备档案。修改已保存机型后点击保存会开始独立诊断，避免旧机型/检查结果带入新机型；需要原记录时可从历史列表恢复，机型冲突仍要求核对。
6. “清空对话”删除本次对话、历史节选和检查进度，保留设备档案。“删除本次诊断”删除该记录；“删除设备及记录”级联删除该设备的所有诊断。清空/删除不会让正在生成的旧回答重新写入。

历史浏览器缓存最多迁移最近38条消息；之后以服务端记录为准。旧的`/api/chat`请求不带`sessionId`时仍按原来的临时上下文方式工作。

## 持久化与身份

- 使用Node原生`node:sqlite`，无需安装外部数据库服务。Node最低版本沿用22.19.0，推荐24；Node可能显示原生SQLite的实验性提示。
- 默认保存到`~/.agridx/memory.sqlite`，支持`MEMORY_DB_PATH`指定绝对路径。该目录与SQLite、WAL、SHM文件已排除Git提交。
- 服务重启须使用同一数据库文件。容器重建、更新代码或迁移服务器时须保留/挂载该目录，不能依赖临时容器磁盘。推荐独立持久目录，例如`/var/lib/agridx/memory.sqlite`，运行账号需有该目录读写权限。
- WAL模式、外键级联、事务和版本检查保证成对保存用户问题/助手回答，拒绝过期的并发写入。新建诊断时，设备归属检查、数量上限检查和写入处于同一写事务，避免多个服务进程并发创建时越过上限。文件权限限制为600。
- 当前没有账户系统：使用随机256位HttpOnly、SameSite=Strict浏览器Cookie作为匿名访问凭据，数据库只保存其哈希归属。在HTTPS请求下Cookie带Secure。设备/诊断编号不能单独授权访问；每次读取、修改和删除均核对归属。
- 这是同一浏览器的匿名记忆，不提供登录、跨浏览器/跨设备同步或Cookie丢失后的恢复。共享浏览器的人也共享此身份。清除Cookie后旧记录仍可能留在后端，但不能直接访问；需要保留记录时请先恢复/管理，不要清除浏览器身份。身份有效期为一年。
- 记忆API禁止跨站访问并使用`Cache-Control: no-store`。数据库故障明确返回503，不伪装成“已保存”或自动清空记录；原临时聊天仍可独立运行。
- 本次实现适用于现有Express/Node服务。Cloudflare Worker不能直接运行`node:sqlite`，将来若恢复Sites Worker部署，需要单独实现D1存储适配。本轮按最新约定暂停所有网站/服务器发布和迁移。

## 记忆使用边界与成本

数据库保存完整记录；调用LLM只发送最近10条消息（约5轮），合计最多12000字符，每条用户最多2000字符、助手节选最多1600字符。较早记录生成最多3500字符的用户原话节选，不额外调用模型压缩；设备档案和当前检查进度分别限额，最多引用3份同设备历史用户检查报告。

节选不是完整语义摘要，不保证记住每个历史细节。服务端用完整的有界用户记录恢复初始症状、机型纠正与配置，机型适用范围和知识库来源门控继续生效。当前问题和用户纠正优先于旧记录，历史检查不能自动证明当前仍正常。助手的猜测保留在对话中，绝不自动写成已确认故障或知识库维修事实。

每个浏览器身份最多100台设备、100次诊断；每次诊断最多2000条保存消息（通常约1000轮）。达到上限需要管理旧记录或新建诊断。消息与进度都是文本，本轮不保存API密钥、不上传照片、不改知识库来源记录。

## API

所有记忆接口使用同源Cookie；标识和机型均须通过后端校验。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/memory` | 当前身份设备及诊断列表，首次建立Cookie |
| POST | `/api/memory/devices` | 创建设备档案 |
| PATCH / DELETE | `/api/memory/devices/:id` | 更新/删除设备；删除级联删除诊断 |
| POST | `/api/memory/sessions` | 为`deviceId`创建独立诊断 |
| GET | `/api/memory/sessions/:id` | 恢复完整对话与设备档案 |
| PATCH | `/api/memory/sessions/:id` | 保存`progress`，必须带当前`revision` |
| POST | `/api/memory/sessions/:id/clear` | 带`revision`清空本次诊断记忆 |
| DELETE | `/api/memory/sessions/:id` | 删除本次诊断 |
| POST | `/api/chat` | 在原字段基础上增加`sessionId`和`revision`，回复增加`memory`和`relatedMemoryReports` |

持久诊断只信任已保存的历史，客户端不能改写之前的回答。首轮可迁移本地user/assistant记录，客户端system记录仍被丢弃。先保存响应中的新版`memory.revision`再发送下一轮；409要求重新恢复诊断，避免重复写入或覆盖其他页签的更新。停止等待/网络断开可能与服务端提交同时发生；遇到版本冲突时恢复历史记录可核对实际保存结果。

## 验证方式

`npm test`使用`node --import tsx --test`，避免tsx CLI临时IPC在受限环境中的权限错误。若运行环境强制HTTP代理，测试本地HTTP目录接口时需要关闭测试进程的代理；例如Linux：

```bash
HTTPS_PROXY= HTTP_PROXY= https_proxy= http_proxy= npm test
npm run build
npm run build:server
npm run lint
```

新增测试覆盖数据库关闭重开、归属隔离、同车型不同车辆、设备更新/级联删除、清空期间的迟到回答、并发与版本冲突、用户摘要边界、长期症状保留、跨诊断用户报告检索、两模型共享记忆、无密钥与外部失败、存储不可用和旧API兼容。外部供应商使用模拟响应，不调用付费API。


## 3.4.0 整合补充

Express 使用持久目录，`MEMORY_DB_PATH` 可指定独立数据路径；默认运行用户家目录，不随版本分目录替换。公开开发预览使用当前浏览器的网站存储，页面有提示；清除网站数据会删除预览记录，不写入正式服务器。当前已接入模块化 API 与诊断服务，浏览器及最新验证以整合回执为准。
