# 本地知识库与外部 AI 协调（3.0.1）

## 不接模型也能先使用

当前无需购买或配置模型：知识检索、机型校验、模式选择、决策原因、资料展示、追问与回退均在本地完成。模拟测试不会向真实模型发请求。以后配置现有支持的Gemini/DeepSeek，自动模式和AI辅助模式即可尝试真实调用。GPT不是必要条件；本次没有新增GPT供应商。

## 三种模式

| 模式值 | 页面名称 | 行为 |
| --- | --- | --- |
| auto | 自动协调 | 先检查机型，再判断是否为能直接引用的资料查阅；否则尝试AI辅助；没有模型则退回本地 |
| knowledge_only | 仅知识库 | 不调用外部模型，只展示资料和追问 |
| ai_assisted | AI辅助 | 先检索，再将资料和对话传给模型；机型冲突仍先追问，无密钥仍退回本地 |

所有模式都先检索，不把资料数量、关键词分数或模型自信当成诊断概率。已有模型路由仍负责主模型失败后尝试另一家；两家均失败后返回本地。

## 自动决策顺序

1. 用户否定机型、表单与文本冲突：本地追问，零模型调用。
2. 用户询问专用故障码含义或标准参数却缺品牌/型号：先追问。该规则采用明确关键词，不能覆盖所有口语。
3. 服务端禁止AI或配置值无效：仅本地；请求体无法绕过。
4. 用户选择仅知识库：本地回答。
5. 自动模式下的严格资料查阅：直接展示原文及限制。
6. 模型供应商配置无效或未配置密钥：本地回复并说明原因。
7. 其余自动/AI辅助问题：调用模型，要求区分手册依据和通用待验证分析。
8. 调用失败：返回本地资料，记录provider_unavailable原因，不向用户泄露密钥或上游原始错误。

## 什么能自动直答

第一版是保守的明确资料查阅，不自动把开放式故障诊断认定为已解决。

必须有品牌和完整型号，当前消息明确要求查阅/原文/手册等；唯一匹配首条技术资料的完整编号或完整章节标题。编号须与启动时加载的来源索引、条目索引和正文章节逐一对应，不能用编号前缀匹配更长编号。资料有非空页码、版次和适用范围，applicability为matched，status有明确的“已核验”肯定句，status/scopeBoundary中没有待核实、待核验、未核验、配置待确认或未知限制。否定、部分、计划或疑问式核验状态不合格；未识别的状态保留为unspecified，不能推断为已核验。仅技术类别计入证据，背景索引不算维修证据。“为什么、分析、比较、诊断”等综合问题不直接走该分支。

现有资料可能仍有市场/配置/序列号待确认，因而不满足直答门槛，这是正常的保守行为。不得为了触发直答删掉资料限制或冒充已核验。测试使用明确标记的合成资料覆盖直答分支，没有向正式知识库加入维修事实。

符合这些规则也只是返回可追溯资料，不是已确诊，更不证明所有车辆适配条件已验证。开放式问题由AI辅助或本地追问处理。

## 配置

网站后端环境变量：

```env
DIAGNOSIS_MODE=auto
ALLOW_EXTERNAL_AI=true
```

- DIAGNOSIS_MODE设置默认模式，允许auto/knowledge_only/ai_assisted。
- DIAGNOSIS_MODE=knowledge_only会强制全站仅本地。
- ALLOW_EXTERNAL_AI=false同样强制全站仅本地，不能被客户端覆盖。
- 模式或开关拼写无效则安全退回本地，并在健康接口显示configValid=false。
- 与LLM_PROVIDER（选择Gemini或DeepSeek）独立。凭据非空不等于调用成功；需在真实部署后验收。
- 密钥只在部署平台的环境变量/秘密中设置，不提交GitHub。

## 接口兼容

POST /api/chat新增可选diagnosisMode字段，缺省使用服务端默认；非法值返回400。原有choices、provider、model、knowledgeSources、answerMode保持。

```json
{"diagnosisMode":"auto","messages":[{"role":"user","content":"拖拉机热车后动力不足"}],"machineType":"拖拉机"}
```

新增coordination字段：requestedMode、effectiveMode、route（local/clarify/ai）、reason、evidenceLevel（none/partial/direct_reference）、llmConfigured。coordinationMessage提供简短原因说明。主动本地回答的fellBack=false；需要AI但无密钥或调用失败为true。模型供应商无效有独立原因llm_config_invalid。决策字段不是概率或准确率。

knowledgeSources保留原字段，新增status原始状态、referenceVerification（verified/pending/unverified/unspecified，仅表示引用资料核验，不是厂家或实车验证）、sourceIndexed（编号与正式索引对应）。不回写或升级正式资料的核验状态。

/api/health新增coordination.defaultMode/configValid/allowExternalAi，不返回密钥。

## 页面

输入框上方提供三种模式；每条答复显示决策原因，刷新后保留该条原因。本地摘要可展开完整资料。服务器关闭AI时模式控件禁用。模式按当前会话选择，不写入正式知识库。
