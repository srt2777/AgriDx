## 一、强化学习方向：GAP——图规划 + 并行工具调用 + 强化学习

- 标题：GAP: Graph-Based Agent Planning with Parallel Tool Use and Reinforcement Learning
- 作者单位（原文所载）：清华大学、华中科技大学、新加坡国立大学、卡内基梅隆大学
- 版本：arXiv:2510.25320v1，2025-10-29
- 链接：https://arxiv.org/pdf/2510.25320
- 项目页（原文摘要所载，未打开核实）：https://github.com/WJQ7777/Graph-Agent-Planning

### 核心方法（原文结论）

1. **问题诊断**：ReAct 式“思考—行动—观测”一次只做一个动作，无法利用互不依赖的子任务之间的并行性；多智能体系统虽能分工，但通信冗余、编排复杂，且底层模型并非为多智能体协调而训练，更多依赖提示工程而非模型原生能力。
2. **依赖图（DAG）规划**：把复杂查询拆成原子子任务，建有向无环图 G=(V,E)，节点是子任务，边 (vi,vj) 表示 vj 依赖 vi 的输出；无边的节点对相互独立，可以并行执行。规划阶段输出结构化图表示（示例格式含节点、depends 属性与 Parallel Groups），再按拓扑排序划分执行层 L0…Lk：同层内所有子任务组成一个工具调用批次同时执行，等全部结果返回后再进入下一层；最后进入综合答案阶段。
3. **两阶段训练**：
   - SFT 冷启动：以 GPT-4o 为后端、按 Chain-of-Agents 蒸馏思路，从 NQ 与 HotpotQA 合成图规划轨迹；过滤标准有三条——去掉少于 3 次检索的过简单样本、保持并行检索与串行检索样本约 6:4、去掉约 2000 token 以上的过长样本；最终约 7000 条高质量轨迹；骨干为 Qwen2.5-3B-Instruct，损失对观测部分做掩码（observation masking），防止环境噪声传播。
   - 端到端 RL：用 DAPO 算法、VeRL 框架微调；奖励函数只有二值答案正确性 R_acc ∈ {0,1}，不设显式格式奖励（作者称格式已由高质量 SFT 与冷启动保证），未来工作可探索多目标奖励。
4. **实验设置（原文结论）**：7 个问答基准——单跳 NQ、TriviaQA、PopQA，多跳 HotpotQA、2WikiMultiHopQA、Musique、Bamboogle；以精确匹配（EM）为指标；嵌入模型 E5、语料为 2018 年维基百科转储；8 张 NVIDIA A100；基线包括 Search-R1、ZeroSearch、StepSearch、Chain of Agents。

### 关键数字 / 结论（原文结论，含一处口径不一致，见下）

- 摘要口径：多跳任务上比最强基线平均高 0.9%，交互轮数最多减少 33.4%，响应长度减少 24.9%，且在域外数据集上保持泛化。
- 表 1（EM，Qwen2.5-3B 骨干）：GAP-3B 在 HotpotQA 42.5、2Wiki 41.7、Musique 18.7、Bamboogle 43.8；单跳 NQ 39.6、TriviaQA 59.1、PopQA 40.1；作者称多跳四项平均比最强基线高 0.9%、比 Search-R1 高 3.95%（按表 1 数值，Search-R1 多跳四项为 37.6/31.7/15.1/37.1，GAP 平均 36.7 vs Search-R1 平均 30.4，差值约 6.3 个百分点，与正文“3.95%”的表述口径不一致，见“口径差异说明”）。
- 效率（正文 §5.2 文字）：HotpotQA 上 GAP 1.78 轮 vs 对照 2.27 轮（降 21.6%）、2Wiki 上 2.03 轮 vs 3.05 轮（降 33.4%）；HotpotQA 响应长度 416 vs 554 token（降 24.9%）、2Wiki 452 vs 567 token（降 20.3%）；HotpotQA 时间成本 168s vs 248s（降 32.3%）、2Wiki 206s vs 262s（降 21.4%）。
- **口径差异说明（本次阅读中发现的不一致，不是推断）**：正文 §5.2 文字说“相比 Search-R1”给出 2.27 轮 / 248s，但表 2 中 2.27 轮 / 248s 对应的是 AFM-RL-3B 一行，Search-R1 一行是 2.69 轮 / 221s；且表 2 的 HotpotQA 准确率（GAP 36.7、Search-R1 25.3）与表 1 同数据集数值（GAP 42.5、Search-R1 37.6）不一致。可能原因包括不同评估子集或不同实验配置，但本次读到的正文未说明两表口径差别。引用 GAP 数字时应注明出处（摘要 / 表 1 / 表 2 / §5.2 文字），不要把各表数字混用；“比 Search-R1 高 3.95%”这一表述与表 1 数值对不上，暂按“未核实”处理，不要引用。

### 与 AgriDx Agent 的直接相关（推断为主，逐条标注）

- **Planner 规划（推断）**：AgriDx 目前是单主题匹配、模板式逻辑链分解、无依赖关系建模。GAP 的 DAG 思路可以直接对应：把一次诊断拆成“查知识—查遥测—查历史—综合”这类子任务时，先标出依赖边（例如“查某部件手册”依赖“先确定部件/主题”，而“查燃油系统”与“查电气系统”在主题未定时可并行），再按层执行。这比上午 PilotRL 的“全局计划线性修正”更进一步：计划不是一条链，而是一张图。
- **Tool Use 工具协调（推断）**：AgriDx 主循环目前是串行、8 秒预算、4 步、同轮去重、无跨轮调度。GAP 提示的最小可落地改法不是训练模型，而是**在提示词/编排层先做“同层并行”**：同一轮内互不依赖的两次知识检索可以合并为一批发出，省轮数、省时间；但必须先解决两个前提——AgriDx 的工具目前是顺序调用且共享预算，并行批次的预算与去重规则未定义；以及并行结果的合并顺序要固定，否则证据顺序会乱。这两点在现有代码里都是未核实状态，记为下一步核查项，不说成已实现。
- **评测方法（推断）**：GAP 的 cost-of-pass（单次成本 ÷ 成功率）比只看准确率更适合 AgriDx：AgriDx 生产走 DeepSeek、按 token 计费，诊断的“答对成本”比“答对率”更贴近运维现实。离线评测（PR #193 那套）可以补两个指标：每条诊断轨迹的轮数与 token 数、以及“答对的平均成本”，与上午笔记里“按故障类别分开展示准确率 + 假阳性/假阴性”合起来，就是一套可直接用的评测口径。
- **要警惕的地方（推断）**：GAP 的收益来自“训练模型原生输出图结构”，只靠提示词模仿图格式不等于获得同样的并行判断能力；且其基准是问答检索，不是农机诊断，0.9% 这类数字不能平移到诊断准确率；RL 阶段只用二值答案奖励，在 AgriDx 场景里“答案正确”本身就难自动判定（没有标准答案库），所以 RL 训练管线仍是远期方向，近期只能借鉴“图规划 + 并行执行 + 成本口径”这三点。

### 对 AgriDx 最直接的一条借鉴（推断）

把 Planner 的逻辑链从“一条模板链”改成“带依赖边的子任务图”，同层无依赖的检索并行发出，并在离线评测里补“轮数 / token 数 / 答对成本”三个效率指标——这三点都不需要 RL 训练管线，是近期可落地的部分。

## 二、深度学习方向：农机振动故障诊断综述（田间激励、信号处理、智能模型与工程部署）

- 标题：Vibration-Based Fault Diagnosis of Agricultural Machinery: A Review of Field Excitation, Signal Processing, Intelligent Models and Engineering Deployment
- 作者：Kuizhou Ji、Zibiao Zhou、Yaoming Li（江苏大学农业工程学院）
- 出处：Machines 2026, 14, 795；收稿 2026-06-21，录用 2026-07-13，发表 2026-07-14
- 链接：https://doi.org/10.3390/machines14070795（本次读到的是 MDPI 提供的 PDF 全文 v2）
- 性质：综述（76 页），不是提出单一新模型的论文；其价值在系统梳理与工程口径，不在某一个准确率数字。

### 核心内容（原文结论）

1. **为什么农机振动诊断比一般旋转机械难**：田间同时存在地面不平、作物流量冲击、发动机激励、传动激励、变速变载、粉尘潮湿等多源激励；故障的弱特征常被非平稳背景振动掩盖，表现为强噪声、非平稳、冲击密集、频率重叠、弱故障特征。综述覆盖的对象包括拖拉机、联合收割机及轴承、齿轮箱、传动系统、割台、脱粒滚筒、清选筛、振动筛、底盘、车架、驾驶室等部件。
2. **智能模型分类（原文表 8 与 §5.7，原文结论）**：
   - 传统机器学习（SVM、随机森林、KNN、ANN）：小/中数据集、可解释、计算量低，依赖手工特征，适合发动机状态、齿轮箱与负载识别；
   - 一维深度学习（1D-CNN、LSTM/GRU、CNN-BiLSTM，输入原始振动段）：自动学局部/时序特征，适合传动与轴承诊断，但数据需求大、对域漂移敏感；文中点名的拖拉机传动系统方法即改进 CNN-BiLSTM；
   - 二维深度学习（2D-CNN、ResNet、ResViT、ViT，输入时频图/谱图）：对时频图像模式表达强，适合图像化轴承诊断，但计算量大、可解释性弱；文中点名的农机滚动轴承方法即 SVD-EDS-GST 预处理 + ResViT；
   - 迁移学习/域自适应（DANN、MMD、对抗迁移）：缓解跨转速/跨负载/跨机器的分布漂移，有负迁移风险；
   - 域泛化：面向无目标域数据的跨工况/跨季节诊断，需多样源域数据；
   - 小样本与不平衡学习（元学习、GAN 数据增强）：处理稀有与早期故障，但有合成—真实差距；
   - 多源融合（特征/决策层融合、集成学习）：振动 + 转速、负载、温度、电流、液压、行驶速度、喂入量、姿态、控制参数等多源信息可提升鲁棒性与故障定位，但需时间同步、标定与一致格式；
   - 图模型（GCN、GAT）：传感器、测点、部件、频带或样本作节点，物理连接、空间邻接、统计相关、相干性或工况相似性作边；文中点名的农机滚动轴承多源局部自适应图卷积即此类，但综述强调图的实际价值取决于“物理上有意义的构图”与稳健验证，纯数据驱动的图易受工况变化影响，纯物理图可能漏掉隐藏耦合；
   - 可解释模型（SHAP、Grad-CAM）：把决策归因到时间段、频带、测点或特征，农机场景下解释应落到轴承故障频率、齿轮啮合边带、振动筛冲击、底盘传递路径或工况变化上；
   - 轻量化/边缘模型（轻量 CNN、剪枝、量化）：面向车载控制器与边缘终端的有限算力、存储、功耗与通信带宽，需连同延迟、内存、鲁棒性与田间硬件可靠性一起评估。
3. **评测口径（原文 §5.6，原文结论）**：只报分类准确率不够。正常样本通常占主导、早期与少数故障稀有，高准确率可能与早期故障预警差并存；应同时报告准确率、精确率、召回率、F1、混淆矩阵、误报率、漏报率与分故障类别识别结果。**数据泄露警告**：把连续信号切成短窗口再随机划分，会让同一采集记录的相邻/高度相似窗口同时出现在训练集与测试集，导致性能高估；田间数据应按机器、田块、作业日期、故障事件、转速、负载或季节划分，并在未见过的机器或工况上测试。还应报告参数量、计算复杂度、推理时间、内存与能耗；并做不确定性处理——低置信时应建议人工检查或补充采集，而不是强行输出一个过自信的故障类别。
4. **结论与未来方向（原文第 9 节，原文结论）**：趋势不是用单一算法替代一切，而是按部件对象、数据规模、故障机理与部署需求组合方法；未来重点是高质量开放数据集、物理信息驱动模型、跨域自适应学习、多源融合、边缘智能、数字孪生、可解释决策与标准化评测；最终要形成监测—诊断—解释—维修—反馈的闭环。

### 与 AgriDx Agent 的直接相关（推断为主，逐条标注）

- **证据结构（推断）**：AgriDx 目前是纯文本知识检索 + 规则路由、无真实传感器接入（遥测为模拟）。这篇综述的价值不在某个模型，而在它的**分层证据观**：振动反映机械动力学，转速支撑阶次分析，负载与喂入量描述工况，温度与电流提示润滑/摩擦/电驱状态，姿态与行驶速度帮助区分机械故障与地形冲击。对应到 AgriDx 的证据结构：未来若接真实信号，诊断结论必须同时说明“信号证据 + 工况证据 + 排除项”，而不是只给一个故障类别；近期可先落到离线评测与回答模板里——要求每条诊断结论附带“工况条件是否已知/未知”的声明，未知工况时降置信度、不强行定性。
- **评测方法（推断，与上午笔记呼应但来源不同）**：上午笔记从 MLP 论文借鉴了“分故障类别 + 假阳性/假阴性”口径；这篇综述补了更关键的两条——**按机器/田块/季节划分、杜绝窗口随机划分式泄露**，以及**低置信时转人工**。AgriDx 现有 17 个合成案例若按随机方式扩增，最容易犯的正是这类“同源泄露”（同一故障模板改几个词就既当训练又当测试）；补案例时应按机型/工况/季节分组划分，并给每个案例标“工况是否完整”，这是比扩数量更优先的评测修复。
- **Planner 主题（推断）**：综述的部件—故障机理对应关系（旋转传动件看转频/阶次/齿轮啮合频率与冲击调制，作业部件受作物流量与多源激励影响大，连接结构关注局部刚度变化与螺栓松动疲劳，底盘与驾驶室关注传递路径与减振）可以直接丰富 AgriDx Planner 现有 6 主题之下的“子机理”维度：同一主题（如传动）下再分“轴承/齿轮/松动/不对中”等机理分支，检索时按机理分支取知识，而不是只按主题取。这仍是提示词/知识组织层的改动，不需要传感器。
- **Tool Use / 工具协调（推断）**：综述的多源融合三层（数据层需严格同步、特征层先提时域/频域/时频/深度特征再加权或注意力融合、决策层各源分别诊断再投票/加权平均/集成）对应 AgriDx 的一种远期工具形态：若将来有振动、温度、电流等多路输入，不应把原始信号直接塞给 LLM，而应先由信号工具出“特征 + 置信度”，再由 LLM 做决策层融合。但目前 AgriDx 没有真实多源数据，这一条只能记为远期方向，且综述本身也提醒“多传感器增加硬件成本与维护难度、图构建仍不确定”。
- **要警惕的地方（推断）**：这是一篇综述，文中点名的方法（CNN-BiLSTM、ResViT、局部自适应图卷积）各自的准确率数字本次未逐项核对，**不要引用任何一个未在笔记中出现的具体准确率**；且综述反复强调“通用轴承/齿轮箱台架方法不能不经适配直接搬到农机”，同理，通用问答基准上的 GAP 数字也不能直接搬到农机诊断——两篇笔记在这一点上结论一致。

### 对 AgriDx 最直接的一条借鉴（推断）

离线评测立即补两条规则，不改线上诊断、不接传感器就能落地：① 案例按机型/工况/季节分组划分，杜绝同源模板泄露；② 诊断结论必须带置信度声明，低置信时明确建议人工检查/补充信息，而不是强行输出单一故障类别。

## 本次两篇的共同点（推断）

- 两篇都反对“只看单一准确率/单一指标”：GAP 用准确率 + 轮数 + 长度 + 成本一起看效率，振动综述用分故障类别 + 误报/漏报 + 鲁棒性 + 可解释性 + 边缘可部署性一起看可信度。AgriDx 的离线评测口径应同时吸收这两套。
- 两篇都强调“结构先于模型”：GAP 是先建依赖图再执行，振动综述是先讲机理与传递路径再选模型。对 AgriDx 而言，近期最便宜的结构改进是 Planner 的依赖图/机理分支与评测的分组划分，而不是上新的训练管线。
