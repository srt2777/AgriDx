## 一、强化学习方向：PilotRL

- 标题：PilotRL: Training Language Model Agents via Global Planning-Guided Progressive Reinforcement Learning
- 投稿：2025-08-15；本次读到的版本注记为 2026-07-28 发布的新版本 v5（alphaxiv 概述页，未读 arXiv PDF 全文，见“阅读边界”）。
- 链接：https://www.alphaxiv.org/audio/2508.00344v2（arXiv 编号 2508.00344）

### 核心方法（原文结论）

1. **问题诊断**：主流 ReAct 范式是单步“思考—行动”交替，缺乏长程战略视角；规划器与执行器分离导致规划不被执行或执行中不被修正；监督微调（SFT）容易让模型记住任务轨迹，泛化差。
2. **AdaPlan 范式**：维护一份显式的高层全局计划。给定任务目标 G 与初始上下文 C^(0)，规划器先生成初始计划 P^(0)（含 N0 个推荐步骤）；执行器按已积累上下文 C^(t-1) 与当前计划 P^(t-1) 行动 a^(t)；收到观测 o^(t) 后，计划被自适应修正为 P^(t)。关键设计：已完成步骤固定，未来步骤可随环境反馈动态更新；规划器与执行器由**同一个模型**实现，以消除分离架构的协调问题。
3. **三阶段渐进式 RL（PilotRL）**，核心算法为 GRPO（Group Relative Policy Optimization），用 verl 框架实现；DeepSeek-V3 在第 1 阶段担任计划生成器、在全部阶段担任奖励评估器：
   - 第 1 阶段·执行器增强：在给定高质量全局计划的条件下学“按计划行动”，奖励 R = 格式分 + 计划服从分 + 端到端分；服从分由前沿模型打分（2 完全服从、1 部分服从、0 不服从）。
   - 第 2 阶段·规划器培养：模型用“生成—选择”策略自己生成全局计划，奖励 R = 格式分 + 端到端分 + 规划质量分；规划质量从正确性、可执行性、规范性三个维度各打 1–5 分。
   - 第 3 阶段·端到端优化：只保留格式分 + 端到端分，优化规划与执行的整体协调。
4. **实验设置（原文结论）**：验证模型包括 Qwen2.5-7B-Instruct、LLaMA3.1-8B-Instruct、Qwen3-8B；域内训练/评估数据集为 ALFWorld、IQA、TextCraft、Wordle，域外泛化评估为 BabyAI、MAZE。

### 关键数字 / 结论（原文结论，含一处版本口径差异）

- 摘要口径：LLaMA3.1-8B-Instruct + PilotRL 超过闭源 GPT-4o 3.60%，比 GPT-4o-mini 高 55.78%。
- 正文口径：同一模型在全部基准平均上超过 GPT-4o 2.35%、超过 GPT-4o-mini 53.90%。
- **口径差异说明**：摘要与正文两个数字不一致，本次读到的概述页未说明两者计算口径的差别（可能是不同基准子集或版本差异），引用时应注明口径、不要把两组数字混用。——此为本次阅读中发现的不一致，不是笔者的推断。
- 其他结论：Qwen2.5-7B-Instruct + PilotRL 比同骨干的 DeepResearcher-7B 平均高 29.47% 以上；PilotRL 比 SFT 基线平均高 9.89%、比普通 RL 基线平均高 7.64%；消融：去掉第 1 阶段下降 4.20%，去掉第 2 阶段下降 4.33%，交换第 1、2 阶段顺序下降 1.58%。

### 与 AgriDx Agent 的直接相关（推断为主，逐条标注）

- **Planner 规划（推断）**：AgriDx 目前是单主题匹配、歧义时不选主题，逻辑链是模板分解。AdaPlan 的“全局计划显式化 + 已完成步骤固定、未来步骤动态修正”可以直接对应：把 Planner 的主题与逻辑链写成一份显式计划随轮次修正，而不是每轮重新匹配一次。注意 AgriDx 的规划目前是模板而非学习到的规划器，AdaPlan 的训练部分不能直接套用，只能借鉴范式。
- **Tool Use 工具协调（推断）**：AgriDx 主循环目前是 8 秒预算、4 步、同轮去重、无跨轮调度。PilotRL 第 3 阶段“端到端只奖最终结果 + 格式”的思路提示：跨轮工具复用（夜间另一条线仍缺口）应该按整条诊断轨迹评，而不是按单轮调用计分；但 AgriDx 现阶段没有 RL 训练管线，这一条目前只能落到离线评测（PR #193 的 evaluateCandidate / compareCandidates 那套）上先做轨迹级评分，不能说成已实现 RL。
- **Memory 记忆（推断）**：AdaPlan 的 C^(t) 累积上下文与“已完成步骤固定”对应 AgriDx 的短期记忆与会话摘要；长期记忆（PR #209 草案的两会话确认晋升）如果要借鉴，应把“已完成步骤”当成已确认事实的来源之一，而不是把所有轨迹都记下来。
- **评测方法（推断）**：PilotRL 用域内 + 域外（BabyAI、MAZE）两套评估测泛化，这一点可直接借鉴到 AgriDx 的离线评测集：现有 17 个合成案例都是域内构造，缺域外/分布外案例；补域外案例比补 RL 训练更优先、成本更低。
- **要警惕的地方（推断）**：PilotRL 的奖励大量依赖 DeepSeek-V3 这样的前沿模型打分（服从分、规划质量分），这在 AgriDx 场景会引入评估者偏见与成本问题；且其基准是 household / 文本世界任务，不是农机诊断，数字不能平移到诊断准确率上。另：AgriDx 生产只走 DeepSeek、Gemini 仅备份，与 PilotRL 的多模型验证设置不同，不要照搬。

### 对 AgriDx 最直接的一条借鉴（推断）

把 Planner 的主题 + 逻辑链做成一份**随轮次显式修正的全局计划**（已确认步骤固定、未来步骤可改），并在离线评测里按整条轨迹评分，而不是只看单轮回答——这是不需要 RL 训练管线就能先落地的部分。

## 二、深度学习方向：农机神经网络故障诊断

- 标题：State Recognition and Fault Diagnosis Method for Agricultural Machinery Based on Neural Networks
- 出处：Jordan Journal of Mechanical and Industrial Engineering, Vol. 20, No. 2, Special issue: Instrumentation & Measurements in Mechanical Engineering, April 2026, pp. 235–246
- 作者单位（摘要所载）：Dezhou Agricultural Machinery and Farmland Construction Service Center, Dezhou Agricultural and Rural Bureau, China
- 链接：https://jjmie.hu.edu.jo/vol20/vol20-2/10-JJMIE-S2E02128R1.pdf（DOI: 10.59038/jjmie/200210；收稿 2025-09-15，录用 2026-02-12）

### 核心方法（原文结论，以摘要为准）

- 面向田间多工况的农机状态识别与故障诊断：用**多传感器输入**（温度、振动、压力、转速），在多种工况下采集。
- 对传感器流做**窗口化特征向量**提取，训练一个**多层感知机（MLP）**，把机器状态分类为正常运行与多个故障类别（举例：发动机、电气、传动、液压故障）。
- 自述新颖点：面向田间的多传感器诊断管线，并且**统一报告**多故障性能、误分类风险与可部署性指标，目标是可变农业负载下的在线监测。

### 关键数字 / 结论（原文结论，以摘要为准）

- 自建多工况数据集上：总体分类准确率 **92%**；正常状态识别 **96%**；主要故障类别的故障类型识别准确率均 **高于 83%**。
- 与传统基于规则的诊断相比：按故障类型不同，准确率提高 **11–15 个百分点**。
- 误分类风险：假阳性率 **2%**，假阴性率 **4%**（测试集）。
- 窗口化推理管线被报告为接近实时可行，支持拖拉机与收割机在变负载下的在线部署；摘要称报告了每窗口平均推理延迟，但**具体毫秒数本次未读到**，不要引用。

### 与 AgriDx Agent 的直接相关（推断为主，逐条标注）

- **证据结构（推断）**：AgriDx 目前是纯文本知识检索 + 规则路由，没有真实传感器接入（遥测是模拟，TELEMETRY_MODE=simulated，种子 2777）。这篇论文的价值不在 MLP 本身，而在它的**报告口径**：多故障分开展示准确率 + 误分类风险（假阳性/假阴性）+ 可部署性指标。这套口径可以直接借鉴到 AgriDx 的离线评测报告里——现在 PR #193 的离线评测只有合成案例得分，缺分故障类别的误分类统计。
- **Planner 主题（推断）**：论文的故障类别（发动机、电气、传动、液压）与 AgriDx Planner 现有的 6 个主题（过热、启动、燃油、电气、液压、传动）高度重合；如果将来要接真实传感器，这篇的传感器清单（温度、振动、压力、转速）就是一份现成的输入清单。但目前 AgriDx 没有真实传感器数据，**不要把这篇的 92% 当成 AgriDx 的诊断准确率**。
- **Tool Use / 工具协调（推断）**：论文的“窗口化特征向量”对应 AgriDx 的一种可能的新工具形态：把连续信号切窗、提特征再查知识库。但这需要真实数据接入与标定，目前不在 AgriDx 的工具清单里，只能记为远期方向。
- **评测方法（推断）**：论文用“自建多工况数据集”评估，这正是 AgriDx 离线评测最缺的：现有 17 个合成案例未覆盖多工况（负载、机型、季节变化）；补多工况合成案例比照搬 MLP 更优先。
- **要警惕的地方（推断）**：MLP + 窗口特征是经典方法，不是新架构；92% 是在作者自建数据集上的结果，未见跨机型、跨季节、传感器退化条件下的表现；且该文与同一期的随机森林拖拉机诊断论文（总体 82.5%）一样，都是小样本、本地数据集结论，不能直接外推到鸿鹄 T70（T70 在 AgriDx 知识库里只有 2 条知识条目、无手册 PDF，数据基础远弱于论文场景）。

### 对 AgriDx 最直接的一条借鉴（推断）

照搬这篇的**报告口径**：离线评测以后按故障类别分开展示准确率，并同时报告假阳性率、假阴性率与可部署性（延迟/成本）——不改线上诊断、不接传感器，就能先让评测结果变得可比、可审计。
