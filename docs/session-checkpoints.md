# 工作进度与续接

每位参与者对自己的任务维护一份可续接的进度摘要。开始或恢复对话时，先核对当前工作区、最新远端、任务关联的 Issue/PR 与记录，说明未完成事项和建议的下一步；仅在任务相关且得到适当授权时继续。若记录与实际状态不一致，以核验后的状态为准。

## 何时保存

在重要阶段完成后、改变计划或遇到阻塞时更新；准备中断或运行环境明确显示额度快耗尽时，优先更新。额度不可见时不猜测；意外中断可能发生在下次保存之前，因此不要只依赖最后一次保存。

优先在已有任务 Issue/PR 或该任务分支保存适合公开的摘要。仓库是公开的，不要发布完整对话、个人信息、访问令牌、密钥或其他不适合公开的内容。涉及私人内容时留在参与者自己的私有位置，只在公开记录中保留不敏感的指引。未经授权不代替参与者发送消息、创建公开记录或归档聊天。

## 记录模板

```markdown
## 任务进度（时间和时区）
- 目标与范围：
- 已完成：
- 未完成及阻塞：
- 仓库、分支、提交及相关 Issue/PR：
- 工作区状态及尚未提交的文件位置：
- 已执行的验证与结果：
- 风险、授权边界及尚未验证的事项：
- 下一步及恢复所需操作：
```

更新同一任务的记录时保留清晰的时间和状态，避免覆盖其他参与者的成果；检查远端变化，遵循仓库分支和 PR 流程。任务完成后标记完成，并保留必要的审阅记录。

## 能力边界

这是仓库协作约定，不是后台监听程序。GitHub 无法直接查看参与者各自的 Codex 额度，也不会因额度恢复自动发出续接提醒；提醒发生在参与者下一次打开或继续相关对话且助手读取仓库规则时。不同工具可能不读取 AGENTS.md，参与者应自行查看本指南。Codex 原会话可以使用其产品提供的恢复方式；这里的摘要不能替代完整会话，也不保证每次执行或自动上传。
