# 部件知识关联验收

日期：2026-10-25（上海）；版本：3.18.0；分支：`codex/ui-parts-knowledge-20261025`。

## 问题 → 解决 → 效果

PartsStudio 详情原来只有示例状态/故障，没有知识条目计数或来源入口。抽屉增加独立“来源归档”知识区，复用目录缓存与查询 hook，不将示例故障文本送入检索。

柴油是通用结构示意，默认不绑定真实机型，用户手动选择资料品牌、型号。映射只提供既有目录查找路径，组件级条数明确“尚未细分到该部件”，不伪装成部件级证据。缺部件索引时显示“待补资料”并打开合法的上级目录；T70 只查自身范围，不借其他设备资料，其两条资料索引不充当电池舱等部件知识。

第3步拆为两个小 PR：本批完成知识关联；聚焦、手机描边、键盘/触屏和二维降级增强仍待后续3b，完成后再开始遥测。保留现有新旧切换、路由、示例标记、液态玻璃及主题。PartsStudio 仍位于原来的新版，旧版模型页保持既有组件与资料入口。

## 验证

- Node 24.22.1 / npm 10.9.4 / Python 3.12.14；先 dry-run 再 feature 脚本从 3.17.0 到 3.18.0，无新依赖。
- `node --import tsx --test tests/part-knowledge.test.ts tests/catalog-cache.test.ts`：11/11 通过。覆盖手选范围、部件/组件区分、T70 独立范围、所有拖拉机目录型号×示意部件查询有效性、唯一计数与过期范围拒绝；现有缓存测试覆盖失败、取消、重试与范围隔离。
- `npm run verify`：561 项，545 通过、16 项 Linux 专用测试在 Windows 跳过、0 失败；版本、知识库哈希、类型、Lint、前后端构建通过。既有 Fast Refresh 和大 chunk 提示保留。
- 使用本地生产构建，禁用外部模型调用；桌面 1440×1000、手机 375×1000 核对。新增 select/link 均为 44px，无横向溢出，键盘焦点清楚。中英文及浅/深主题可读；模型和知识查询独立标签控制台无错误。
- 选择柴油散热器时首先显示“资料范围待核实”，没有默认真实机型。选择纽荷兰 WORKMASTER25 后显示加载状态，再显示 **3 条**；切发动机保留资料范围并显示“组件级资料”。
- 用键盘进入 `view=machine&brand=纽荷兰&model=WORKMASTER25&component=cooling&part=radiator`，目录显示3条，保留书名/页码/适用范围与核验说明。切回工坊默认 T70；电池舱显示待补资料，链接固定鸿鹄/T70，不生成不存在的部件 URL。
- 新区提供加载/失败重试/缺资料状态；没有对失败请求展示推测数值。此批未通过断网人为制造失败截图，失败/取消/重试沿用已测试的目录 hook；不宣称做过未执行的视觉故障注入。
