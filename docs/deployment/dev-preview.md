## 自动更新与管理

从最新 `origin/main` 建立个人任务分支，完成改动并运行对应验证，保存 PR。PR 按仓库既有规则审阅并合入 main 后，Actions 自动执行完整验证、构建、快进更新 `dev-preview-built` 产物分支。Sites 入口只读取该固定仓库的构建，保持同一网址，无需重新创建站点。

构建一般约2分钟，排队时会更久，并非每次按键实时上线。3.5.1起，已打开网页进入时及每30秒检查新构建，恢复前台、联网或聚焦时立即检查；知识页等安全浏览页面确认新HTML与发布提交一致后自动加载，无需点击刷新或给助手发消息。诊断请求、未保存草稿/设备/检查进度及本地照片/GLB期间延期，保护解除后自动继续；不会清空浏览器记录。筛选随URL保留，不同设备的会话仍分别保存。生产站采用相同机制，详见[网页自动加载](automatic-client-update.md)。

若需要重跑当前 main 的预览，可在已配置 GitHub 访问的仓库中执行：

```bash
npm run preview:publish
# 相当于仅派发 main 的工作流，不提交、不推送、不合并个人分支
# 查看运行结果
gh run list --workflow dev-preview.yml --branch main
```

也可在 GitHub Actions 的 `Development preview` 工作流选择 main 后手动运行。工作流和产物发布代码同时核对 main、仓库及最新源码 SHA；旧构建不得覆盖更新后的主干。旧 `dev-preview` 分支保留历史，不再作为发布源。

本地检查与构建入口继续可用：

```bash
npm run verify
npm run build:dev-preview
```

预览使用现有真实知识目录、型号边界、会话解释及本地 RAG，通过构建时只读资料快照在浏览器运行；包含已索引的 Markdown 与目录元数据，不包含原始手册、环境文件和模型密钥。外部 Gemini / DeepSeek 未接入该开发网址，界面标明本地知识检索。3.4.0 起，设备档案、完整对话与检查进度仅保存在当前浏览器的网站存储，支持恢复、清空和删除；不会发送到腾讯，清除网站数据会删除这些预览记录。
