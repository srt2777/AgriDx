# Unreal Pixel Streaming 方案（AgriDx 旧版首页，第一步）

> **本 PR 的范围，先说清楚：本 PR 不含虚幻工程文件，不含服务器，流未接通。**
> 本 PR 只含两样东西：(1) 旧版首页内的网页播放器
> （`src/pages/HomePage/sections/PixelStreamHero.tsx`，官方像素流库 +
> 网页版 T70 回落模型）；(2) 本文档——把虚幻工程做出来的方案。
> 在服务器与虚幻流上线之前，旧版首页显示的始终是回落的网页版 T70
> 模型，播放器区域明确显示“像素流未接入”。不要把回落画面说成实时流。

## 1. 目标与非目标

- 目标：旧版首页出现一个可交互的鸿鹄 T70 实时画面——用户在网页上
  拖动 / 点选零件，虚幻端相机跟随、标注信息回传网页；断线可重连；
  手机端可用；流不可用时自动回落到网页版 T70 模型，不白屏。
- 非目标（本 PR 不做）：虚幻工程本身、GPU 服务器采购与部署、
  账号 / 权限体系、新版首页的任何改动、诊断 / 知识 / 聊天业务逻辑。

## 2. 虚幻版本选择

- 推荐：**Unreal Engine 5.6**，与网页端已接入的官方前端库
  `@epicgames-ps/lib-pixelstreamingfrontend-ue5.6`（本 PR 核实时最新
  `0.3.1`，2026-11-01）同代，避免跨代协议不一致。
- 备选：UE 5.5（前端库 `lib-pixelstreamingfrontend-ue5.5` 1.3.0，
  更成熟的 1.x 线）。只有当团队已有 5.5 工程或插件资产时才选，
  且网页端依赖要同步换成 5.5 的包——不要 5.5 工程配 5.6 前端库。
- 注意：UE 5.5 起 Epic 同时提供 Pixel Streaming 与 Pixel Streaming 2
  两个插件（过渡期并存）。本方案用经典 Pixel Streaming 插件路线，
  因为网页端官方库与 Cirrus 信令是按这条路线设计的；如果将来改走
  Pixel Streaming 2，要按官方迁移指南重核前端库与信令，不可只换包名。

### 插件开启步骤（虚幻编辑器内，逐项核对）

1. 新建空白项目（模板不限，推荐 Third Person 或 Blank，避免自带
   内容干扰取景），项目名与 AgriDx 仓库无关、单独建仓管理。
2. `Edit > Plugins` 中搜索 Pixel Streaming，勾选启用（经典插件），
   重启编辑器。
3. `Project Settings > Plugins > Pixel Streaming`：确认编码器、分辨率
   上限与帧率与服务器 GPU 能力匹配（先求稳：1080p / 30fps 起步，
   跑通后再提参数）。
4. 打包前在 `Project Settings > Packaging` 确认目标平台为 Windows
   （Cirrus + Pixel Streaming 的常规服务端组合），并按第 5 节起信令。

## 3. T70 GLB 导入虚幻的方法

模型来源（仓库已有，导入时以它为准，不要另找一个“差不多”的 T70）：

- 文件：`public/models/t70-parts/t70_parts_meshopt.glb`（4,211,108 字节，
  Meshopt 压缩，照片贴图）。
- 配套：`public/models/t70-parts/parts.json`（共 14 个零件、248,990
  三角面；单位 metre；glTF Y-up）。
- 14 个零件：battery_box 电池舱、body_shell 车身外壳、gps_antenna
  GPS 天线、hub_fl 左前轮毂、hub_fr 右前轮毂、hub_rl 左后轮毂、
  hub_rr 右后轮毂、roof_cap 车顶盖、sensor_roof_l 左顶传感器、
  sensor_roof_r 右顶传感器、wheel_fl 左前轮、wheel_fr 右前轮、
  wheel_rl 左后轮、wheel_rr 右后轮。

### 导入步骤

1. 虚幻编辑器 `Content Browser > Import`，选中 glTF 文件；或使用
   glTF 导入插件（按所选 UE 版本的官方文档勾选对应导入器）。
2. 材质 / 贴图：照片贴图是模型外观的全部依据。导入后逐个材质检查
   Base Color 贴图是否挂上、是否被顶点色覆盖——网页端
   `load-parts-tractor.ts` 曾处理过“COLOR_0 顶点色盖住照片贴图”
   的问题，虚幻端也要做同样的检查：贴图优先，顶点色不参与最终颜色。
3. 单位与朝向：源文件单位为 metre、Y-up；虚幻为 Z-up、厘米单位。
   导入时按官方 glTF 导入的单位 / 朝向换算核对：落地后量一下
   整车长、宽、高是否与源数据量级一致（车轮中心高度约 0.19 m、
   车顶约 0.54 m 的量级关系不能颠倒），朝向以前进方向为 X 轴正向
   为准（与 parts.json 的前后轮位置一致），不要凭感觉旋转。
4. 碰撞与分段：**不要把 14 个零件合并成一个静态网格。** 每个零件
   保持独立的 Static Mesh / Actor，以便点选；每个零件生成简单碰撞
   （盒体或凸包即可，车轮可用圆柱近似），碰撞只用于射线点选，
   不做物理仿真。
5. 导入后验收：14 个零件逐个点名核对（英文 id 与中文名一一对应，
   见上表）；缺一个、错一个都算导入失败。

### 绝对不要编造的内容

T70 文件里只有上面 14 个外壳 / 车轮 / 传感器件，**没有发动机、
变速箱、PTO、液压提升等内件**。虚幻场景与网页标注卡都只写这 14
个零件的中文名；没有的零件、参数、维修说明一律不写、不建模、
不“示意”。如果将来拿到带内件的 T70 模型文件，另起一轮核对，
不要在本方案里预设。

## 4. 场景搭建要点

贴合旧版首页的深色电影感，但**不要照搬 MotionSites 的文案与版式**
（那是第三方作品的表达，不是 AgriDx 的资产）。

- 地面：深色哑光地面 + 细腻的反射（不要镜面），加一圈柔和的
  地面光晕把车体从背景里托出来；不要放 AgriDx 之外的品牌元素。
- 灯光：主光（暖白、带阴影）+ 轮廓光（冷色、从车后上方打亮边缘）
  + 环境光补底；阴影开柔和模式，避免生硬黑块。
- 相机：默认机位为整车 3/4 侧面、略高于车顶的视角，整车完整入画
  且四周留白；点选零件时相机平滑移动到该零件前方、距离按零件
  尺寸缩放（与网页回落模型的“按包围盒取景”思路一致，不要写死
  一个只对某个机型成立的机位数字）。
- 背景：纯深色渐变或极淡的雾效，不要照片墙、不要滚动文案，
  画面主体永远是车。
- 性能：248,990 三角面在桌面 GPU 上不算大，但流端仍要开
  Nanite / LOD 视情况而定——先以原始网格跑通，再按实测帧率决定
  是否优化，不要为“好看”提前合并或减面破坏零件分段。

## 5. 零件交互怎么做（网页 ↔ 虚幻）

用官方支持的机制，不要编一个不存在的 API。

- 点选：虚幻端用射线检测（Line Trace）命中零件 Actor，
  命中后做两件事：(1) 该零件高亮（材质自发光或描边）、其余零件
  变暗；(2) 相机平滑聚焦到该零件。
- 标注信息回传：走 Pixel Streaming 的数据通道双向消息机制——
  网页端官方库提供 `emitUIInteraction(descriptor)` 向虚幻发送
  JSON 描述符；虚幻端用 Pixel Streaming 的“接收 UI 交互”蓝图节点
  / C++ 回调接收，并用对应的“发送数据到网页”机制把选中零件的
  id 与中文名发回网页。网页端监听官方库的数据通道事件后更新
  标注卡。**具体节点名与消息结构以所选 UE 版本的官方文档与
  PixelStreamingInfrastructure 示例为准**，本方案不虚构节点名；
  实现时先跑通官方示例的双向消息，再把零件 id 接进去。
- 网页端输入透传：本 PR 的播放器已按官方库做法实现——把
  `videoElementParent` 交给库，库在该元素上挂鼠标 / 键盘 / 触屏
  处理，并受 `MouseInput` / `KeyboardInput` / `TouchInput`
  标志控制。虚幻端不需要、也不应该再写一套“网页鼠标映射”。

## 6. 服务器与网络清单

只写范围性提醒，不写具体厂商价格、不写任何真实服务器地址。

- GPU 服务器最低配置：带 NVIDIA GPU（支持硬件视频编码）的
  Windows 服务器；显存与型号按 1080p / 30fps 单路流 + 并发路数
  实测选型，先单路跑通再谈并发。Linux 不是本路线的首选服务端。
- 操作系统与打包：Windows Server / Windows 桌面版均可跑虚幻打包
  产物；打包产物与信令服务放同一内网或同一台机器起步最简单。
- 信令服务器（官方 Cirrus 方案）：使用 Epic 官方
  PixelStreamingInfrastructure 仓库里的 Cirrus 信令服务
  （Node.js 实现），不要自己写 WebSocket 信令。起法按该仓库
  README：安装依赖、配置端口、启动 `cirrus`，再启动虚幻打包
  产物并让它连接 Cirrus；网页端连的也是同一个 Cirrus 地址。
- HTTPS / WSS：网页是 HTTPS 时，信令必须走 `wss://`，否则浏览器
  混和内容策略会拦截；内网测试可用 `ws://`，上线必须配证书。
- STUN / TURN：同局域网可先不配；公网用户与 NAT 后的观众需要
  STUN，严格 NAT / 企业网用户需要 TURN（TURN 要带宽成本，
  按并发路数评估，不要默认“人人直连能通”）。
- 端口与防火墙：放行 Cirrus 信令端口（默认 80 / 443 段，按部署
  改）与 WebRTC 媒体端口段；云厂商安全组与系统防火墙要同时放行，
  只开一处等于没开。
- 并发与成本：每路观众 ≈ 一路 GPU 编码 + 一路带宽；并发路数
  上限由 GPU 编码路数与上行带宽共同决定。没有做过并发压测前，
  不要对外承诺“不限人数”。成本按“GPU 服务器 + 带宽 + TURN
  流量”三项分别估算，不要用一个总数糊弄。

## 7. 网页端怎么指向流

- 配置项名：`VITE_PIXEL_STREAMING_URL`（构建期环境变量，Vite 只
  把 `VITE_` 前缀的变量暴露给浏览器代码）。
- 填什么格式：Cirrus 信令的 WebSocket 地址，例如
  `wss://<你的信令域名>:<端口>`（上线）或 `ws://<内网地址>:<端口>`
  （内网测试）。这里不写真实地址——地址由部署方在部署时填。
- 填什么不该填：绝不填密钥、token、密码、内网管理地址。这个
  变量会进浏览器构建产物，任何人打开网页源码都看得到。
- 生效方式：改变量后重新构建前端（`npm run build:client` 或
  完整构建），刷新页面；播放器顶部会从“信令地址：未配置”变为
  “已配置”，“连接像素流”按钮变为可用。
- 地址为空：播放器显示“像素流未接入”，下方回落模型正常工作。
  地址格式不是 ws/wss：播放器判为连接失败并提示格式问题。
  地址可达但无在线流：信令会返回失败或超时（播放器 20 秒安全
  超时兜底），同样回落。

## 8. 验收清单（流接通后逐项测，缺一不可）

- [ ] 画面：整车完整入画、颜色与照片贴图一致、无花屏、无黑屏。
- [ ] 延迟：本地局域网与公网各测一次，记录实测往返感受（不要
      写“低延迟”这种无法复核的词，要写实测条件与结果）。
- [ ] 鼠标键盘：拖动旋转、滚轮缩放、点选零件、键盘漫游（如有）
      在流端与网页回落端表现一致。
- [ ] 断线重连：杀掉虚幻流 / 断网后，网页端出现连接失败并可
      “重新连接”；恢复后画面回来，状态文案正确。
- [ ] 手机端：390 宽下播放器、按钮、回落模型均不溢出、不裁切；
      触屏旋转与点选可用。
- [ ] 回落：信令地址清空后，首页回到“像素流未接入 + 回落模型”，
      不白屏、不死转圈。
- [ ] 旧版回归：首页文案、导航、搜索、语言、主题、新旧版切换、
      侧栏、手机抽屉逐项点一遍；新版文件零改动（以 diff 为准）。
