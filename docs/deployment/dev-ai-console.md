# 开发控制台 API 接入（3.25.0）

入口：开发站 `/#/developer` → GitHub 管理员/维护者登录 → **API 接入**。只作用于开发站；正式 Node 服务原有 `.env` 和模型路由不由此页面修改。

## 使用

1. 在 DeepSeek、Gemini 或 OpenAI compatible 卡片填写服务商 API Key、账号支持的模型 ID 和 API 基础地址，勾选启用并保存。
2. 保存后密钥输入框清空，服务器永不返回原密钥；后续留空表示保留原密钥。保存配置不代表连接已验证。
3. 点击“测试连接”，验证已保存的模型、地址和密钥；未保存的修改必须先保存。测试和调试均会请求所选服务商，可能产生用量。
4. 在“开发站公开调用”中选择已启用的默认服务商，设置上海自然日请求上限并开启“允许所有访客使用 AI 辅助”。初始关闭，默认上限 100 次，可设 1–1000 次。
5. 所有开发站访客都可在智能诊断中使用 AI。自动模式沿用既有协调规则，直接资料答复/身份澄清等仍可只走本地；“AI 辅助分析”可显式选择，“仅本地知识库”不请求模型。
6. 失败、超时、限频或额度耗尽时，保留本地检索和安全答复。管理员调试区仅用于验证模型，不将调试回答标成已核验的维修结论。
7. 删除默认服务商会同时关闭公开 AI；删除操作需在页面内确认。

DeepSeek/Gemini 的预填模型名沿用现有项目配置，不宣称服务商已提供这些别名；请填写当前账号支持的模型 ID，并以真实连接测试结果为准。

DeepSeek 官方接口默认使用 `https://api.deepseek.com` 和 `deepseek-flash`。开发网关对官方 DeepSeek 接口明确关闭思考模式，以适配连接测试及诊断回答的有限输出和等待时间；其他供应商及自定义接口不增加此参数。实际可用性仍需使用管理员账号配置并测试。

## 存储与鉴权

- 复用既有 GitHub 仓库管理员/维护者验证、到期会话、HttpOnly/Secure/SameSite Cookie 与同源写入检查。匿名访客不能读取或修改 API 配置。
- Key 使用 AES-256-GCM、随机 12 字节 nonce 加密，供应商 ID 作为附加认证数据；D1 只保存密文。加密根密钥不进入数据库或源码。
- 页面不将 API Key 写入 localStorage/sessionStorage，不在读取接口回显密钥；上游错误正文、重定向、网络异常细节及可能回显密钥的内容均不转发。
- 根密钥通过 Sites 原生运行时配置保存为 **secret**：`DEV_AI_ENCRYPTION_KEY`，值为独立随机生成的 32 字节、编码成 64 个十六进制字符。首次部署前配置，后续保留；丢失或更换后须重新输入各服务商密钥。
- 默认允许 `api.deepseek.com`、`generativelanguage.googleapis.com`、`api.openai.com`。中转服务需由部署管理员通过 `DEV_AI_ALLOWED_HOSTS` 增加精确主机名（逗号分隔）；网页不能自行扩大许可范围。只支持 HTTPS、无用户信息/查询参数/片段、无非标准端口的基础地址；不跟随重定向。
- 新增迁移 `0001_nice_kronos.sql` 只增加 `preview_ai_providers` 和 `preview_ai_settings` 两表；保留原访问、问答、会话及限频数据，不在请求中建表。

## 公开调用边界

- 只接受同源 JSON POST，经服务端已保存的默认配置调用；浏览器不能指定 API Key、上游 URL、模型或默认服务商。
- 每网络地址每分钟 6 次；站点全体访客共享每日上限，计数以 SQLite/D1 原子语句扣取，竞争请求也不能超额。失败尝试可计入额度，不把计数称为服务商账单或 token 用量。
- 上下文总计最多 18,000 字符，请求体最多 64KB；历史复用既有 recentMessages 限额，当前问题不超过 2,000 字；单次模型输出最多 1024 tokens、20 秒上游超时、响应读取最多 128KB。
- 上游返回的内容继续走既有 `createDiagnosticService`：知识检索、机型隔离、协调、来源限制与 `filterDiagnosticAnswer` 不另写一套；服务端固定提示不允许浏览器替换。
- 对外模型状态只显示是否启用及服务商/模型名称，不返回配置记录、管理员或密钥。浏览器状态缓存最多 10 秒；服务端每次生成都会重新核对开关和额度。
- “使用记录说明”说明 AI 开启时问题及筛选参考资料会发送给所选服务商；仅本地模式不外发给模型。

## 部署

须沿原仓库分支/PR 与开发站发布流程，保留 `.openai/dev-preview.json` 中的项目身份及原 DB：

1. 审阅并合入本批源码，前端经既有 Development preview 工作流生成产物。
2. 使用原开发 Site 的有权限账号打开其源码项目，配置稳定的 `DEV_AI_ENCRYPTION_KEY`（secret），按需配置额外许可主机。
3. 从干净、已提交的本仓库运行 `node scripts/dev-preview-gateway/prepare-site.mjs /absolute/existing-development-site-checkout`。
4. 网关构建将 `ai.js` 与 `worker.js` 合为一个无运行时相对导入的 Worker，并携带追加迁移；经 Sites 保存并部署，平台应用迁移。
5. 管理员本人在页面输入自己的服务商密钥、测试连接，再开启公开调用。代理未获得或代填任何真实服务商密钥。

新前端遇到旧网关或未配置的服务时保持本地诊断，API 管理页显示错误；这不代表网关已经升级。配置没有复制到正式站或其他 Site。

### 生成密钥加密根密钥

在可信终端运行 `npm run dev-ai:keygen`，将输出的 64 位十六进制随机值保存到 Sites 运行时 secret `DEV_AI_ENCRYPTION_KEY`。工具不写入项目文件；不要把输出粘贴到聊天、仓库、日志或公开产物。根密钥丢失或更改后，已有密文无法解密，需重新输入所有服务商密钥。`DEV_AI_ENCRYPTION_KEY_PREVIOUS` 双密钥轮换仅为后续规划，当前未实现。

### 一步接入与验证状态（本次源码实现）

开发者登录后填写密钥，选择“保存并启用”；如果模型留空，网关先请求同一白名单地址的 `/models`，选择服务商占位推荐模型（若存在）或列表中的第一个 ID，再进行一次最小连接测试。列表不可用或选出的模型无法测试时，页面要求手动选择或填写；占位型号本身不是可用性承诺。也可以提前获取模型建议，列表不包含所填模型时显示提示。所有模型请求不跟随重定向、沿用响应大小限制及主机白名单。

只有连接测试成功后才在一次 D1 批量事务中写入 AES-256-GCM 密文、启用状态、验证时间与耗时；失败不会保存此次输入。尚无已配置默认服务商时自动设为默认。可勾选“同时向访客开放（每日上限 100）”；当已有默认服务商时，公开请求仍使用已选默认服务商，默认服务商必须启用且最近一次测试成功。明确测试失败会更新失败分类并暂停公开调用。输入密钥仅在页面内存保留，离开页面后销毁，不存入浏览器持久化存储。

`GET /api/dev-admin/ai/readiness` 仅允许已验证管理员读取加密、迁移、网关能力、已验证服务商与公开调用状态。新增 `0002_worried_iron_patriot.sql` 是追加迁移，不更改原迁移。网关健康与管理员会话返回版本、schema、能力和源码哈希；前端检测旧网关时提示重新部署，不执行新的接入写入。

公开调用的主服务商遭遇超时、限频或上游 5xx 时，依次尝试其他已启用且最近测试成功的服务商；鉴权和模型错误不盲目回退。同一请求在尝试前原子扣减一次日额度，回退不额外扣减；全部失败时客户端继续走本地诊断。开发调试测试可能产生服务商用量。

准备开发网关：`node scripts/dev-preview-gateway/prepare-site.mjs --site "AgriDx v4 开发版" <站点 checkout 绝对路径>`。脚本核对登记的 project_id、D1 绑定、源码和目标工作区状态，保留已有迁移，复制入口及追加迁移，生成源码哈希；它不自行发布。需要所有者在 Sites 保存并部署网关、应用迁移并设置 secret，随后核对 `/api/health` 和 `/api/dev-admin/session`；GitHub 前端更新不代表网关已升级。

### 后续工具调用透传（未启用）

当前 `capabilities.toolCalls=false`，网关只接受受限的 system/user/assistant 文本。未来传递 `tools`、`tool_choice` 和 tool 消息前，需限定工具名与 JSON Schema、工具参数及响应大小、调用数、重复和时间预算，禁止客户端声明其他用户的身份；只允许受审只读工具。每次模型上游请求和多步循环的每日额度计量规则需要先明确并测试，不能把一次循环中的多个调用悄然当作一个免费请求。当前没有实现透传或开放该能力。
