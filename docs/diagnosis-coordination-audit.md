## 可复现的原因

| 层级 | 实际检查结果 | 影响 |
| --- | --- | --- |
| 开发预览 | main和#102的浏览器适配器都强制knowledge_only，供应商不可配置，健康状态allowExternalAi=false | 静态预览不可能调用外部AI；服务端设置Key不能改变纯浏览器适配器。保留安全边界，新增正文说明，不在浏览器放Key |
| main检索 | 指定的完整旋耕水温问题命中0条，但登记了LF1504手册 | 0条不是没有该机手册。配置可用的测试供应商时，该问题实际进入AI且调用1次，因此“所有零命中都不调用AI”不是事实 |
| 未知风险路由 | “水温过高怎么办”命中0/参考不足时，通用“怎么办”被当作维修操作，返回unknown_operation_risk | 在两基线下均能复现0次模型调用，普通求助被过早终止 |
| #102候选安全门 | `LF1504水温过高通常表示散热负荷增加。`被宽泛的字母数字故障码正则识别为代码释义 | 在实际检索和HTTP链路中，供应商适配器调用了1次，但答案变成output_rejected、AI补充消失。这是#102未合并代码的问题，不能归因于当前main线上部署 |
| #102整段拒绝 | 一段正常原因分析加另一段无依据9MPa或危险步骤，会令整份回答回退 | 有用的一般原因同时丢失，留下模板式追问 |
| 降级与显示 | 失败类别只保留为provider_unavailable；页面先显示本地模板、后显示AI | 用户难判断是否真正调用、为何失败，分析被大量本地前导内容挤到后面 |

供应商默认模型字符串是否被实际服务接受，当前也未经真实API验证。`configured=true`只意味着Key非空，不证明鉴权、模型名称、网络和响应可用。

## 最小规则修改

1. “怎么办、怎么处理”等普通求助不再因未知风险直接拒绝；明确拆卸、拆装、调压等侵入式请求继续保护。高风险制动/转向/PTO/带压操作、身份冲突、服务端禁用、无效配置和仅知识库模式原有限制保留。
2. 不匹配的文献继续从来源与prompt中硬排除；缺少可用文献可调用AI做通用分析，不将文献不匹配混同为用户设备身份冲突。
3. 安全门接收当前已识别车型，排除该车型编号的误判；P1234等OBD形状、显式“故障码LF1504”等释义仍需适配原文。数字、来源、页码与危险动作检查不放宽。
4. 以独立段落为单位检查。当整份输出有问题，只保留独立且安全的原因解释，不保留可能失去前置条件的维修步骤；无法安全保留则用本地停机、外部观察、记录建议降级。不再调用模型改写，无额外分类请求。
5. 无依据的“就是水泵坏了”等确定性结论仍拒绝。保留“可能涉及冷却液不足或散热器遮挡”等一般假设，明确不是本机确诊。
6. prompt要求系统解释、条件相关的常见方向、低风险到专业检查的顺序与最多两个关键追问；排序是建议排查优先级，不编造概率。已有本地事实仍保留引用，AI推断分开展示。
7. AI已有追问时不追加本地重复追问，AI正文移到通用本地建议前。无Key、配置禁止、超时、内容被拒时给简短真实说明。保留日志不记录原始用户信息的边界。

## 上线条件与剩余问题

- 需在有Node后端的环境安全配置服务端Key、服务商实际支持的模型名和网络出口；不把Key放入VITE变量、静态页面或提交记录。静态开发预览仍仅本地检索，本轮不增加未授权的公共AI代理。
- 真正验收必须对指定问题及第二轮补充执行真实调用，检查raw响应、最终安全处理、trace与可用来源。不得只凭health的configured标志认定成功；目前没有这些真实模型结果。
- 请专业人员审核原因优先级和初查步骤。规则门不能证明自由文本完整语义正确，段落恢复偏保守；不存在本轮测得的诊断准确率。
- 完整验证结果见PR。当前本地结果：532项测试，530通过、2项平台跳过；Python、三套TypeScript、Lint与前后端构建通过，Lint只有既有Fast Refresh警告。独立预览构建通过。没有修改原始知识、审核状态、诊断数据库结构或生产配置。
