# 发动机过热认知数字孪生原型

入口：智能诊断页面上方的“发动机过热”链接，或 `/#/cognitive-twin`；新版命令面板可搜索“认知孪生”。适用于新版和旧版界面。该原型是规则驱动的证据工作台，不宣称已接入实车或完成独立诊断效果评估。

## 已实现流程

建立绑定设备编号的独立案例 → 记录带来源和时间的温度显示/工况 → 检查机型配置与观测新鲜度 → 查看同一手册的 11 条候选原因 → 追加支持/冲突/无法确定的检查报告 → 记录人工确认及复测声明。全部事件可回放、导出、删除；带摘要去聊天只填草稿，用户确认发送才调用已有诊断服务。

模型范围为 T1254B / T1404-B，手册 SRC-NH-T1254B-T1404B-91783224（2022 年 1 月第 1 版），原档案指向 PDF 288 / 印刷 8-2 页。`shared/overheat-evidence.json` 仅为现有索引的 11 条元信息投影；测试核对编号、题名、来源、页码和审核状态，未增加知识总量。原文仍由知识目录提供，本批未重新逐页审核原手册。

## Agent 要素

- Memory：独立浏览器 IndexedDB 案例事件日志，不旁路现有诊断记忆 API。设备身份和来源建立后固定；纠正身份新建案例。每案例最多 500 事件、每浏览器最多 100 案例，支持 JSON 导出。未保存的表单不属于事件。
- Planner：纯函数 `analyzeTwin` 一次分析；适用性与信息缺失优先，随后按原表顺序提示未知候选的检查报告。没有概率排序、最优检查选择或自主工具循环。
- Tool Use：本地事务读取/追加/删除案例与已有知识链接；案例 revision 在同一读写事务内校验。相同事件 ID/内容幂等，不同内容拒绝；过期版本拒绝，已删除案例不可被迟到写入复活。错误明确展示且不提前更新成功状态。
- LLM：原型规则层不调用 LLM。用户选择“带摘要继续诊断”后，经现有聊天草稿确认路径使用既有模型和来源约束，不改变旧诊断路由。

## 来源、边界和隐私

来源只支持 simulated 和 user-reported，不能通过该页面声称数据来自真实传感器。仿真案例和人工报告分别绑定案例，禁止跨来源追加。观测录入时刻为当前时间；温度是报告显示值，不自动判定过热。-50～200 ℃ 是录入合理性边界，不是 OEM 正常范围。30 分钟仅是原型的新鲜度策略，观测或检查过期后要求更新。

型号未知、配置未确认时专用候选不可适用；Visctronic 风扇需明确装配。保存检查前也在纯函数层执行相同门控，不能只靠前端禁用按钮。支持报告不等于确诊，冲突报告不等于永久排除；历史矛盾始终保留。人工确认须先有有效观测、适用性和支持报告，并填写确认人、复测记录；仅记为提交者声明。任何新观测或检查重新开启分析。新观测之后必须重新提交检查；此前检查保留为历史，不继续支持当前观测的候选。不能将这些事件自动提升为公共知识库事实或训练数据。

数据只在本浏览器的本源站点数据库；不是云端账户同步。共享浏览器共用数据，清除站点数据会丢失。导出仅包含用户主动选择的本案例；没有网络上传、遥测采集、模型训练或板端部署。记录确认人时可使用内部代号。
