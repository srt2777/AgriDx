选择 `feat/agent-tooluse`，基于 `origin/main` 的 `2f206e9`；这是用户明确指定的名称，覆盖仓库默认 `codex/` 命名前缀。备选为复用 `codex/agent-tool-loop`；该分支已有独立 PR #161，复用可能混淆两项工作及其验收，因此先作为参考，不覆盖它。

## 2026-10-28：真实数据优先，严格行为隔离

仓库已有真实索引和通识资料，不生成样例数据替代它们。现有无机型检索规则与本次要求不同：新入口须在缺机型时追问，并默认关闭；保留现有产品路径直至兼容性得到验证。备选直接修改全局检索会改变现有功能，不采用。

## 2026-10-28：保守适配和可审计的体检

选择独立严格适配器复用现有检索，拒绝未绑定索引或未经核验的片段，暂不接入用户流程。备选直接替换现有检索会改变主线用户行为且缺少质量评测。体检先统计真实索引与来源关系，明确不声称检查正文或扫描表格；后续增加解析与增量索引后再扩展。

## 2026-10-28：增量导入使用完整快照语义

按 `doc_id + version` 与完整元数据/正文哈希检测变化，缺席文档仅记录移除；暂存结果不写入现有知识库。备选对现有归档直接重建存在误删和未核验内容进入诊断的风险。Markdown 过长章节拒绝处理，避免截断表格。

## 2026-10-28：新工具注册表保持隔离

先实现强制确认、参数校验及角色权限边界，不将其接入现有聊天，也不信任模型自行声明确认。超时信号只协作取消，不能承诺取消所有已经发生的副作用；上线前仍需可信确认、持久审计及测试。


## 2026-10-28：先交付可运行的严格资料定位纵向流程

复用主线快照和机型适用性，增加 BM25 与现有关键词排序的 RRF 融合，故障码先在整代快照共匹配。备选直接替换主线聊天会影响已有通识策略；选择新建默认关闭的 Node API 和按服务能力显示的前端入口。原工具循环 PR #161 保持独立，未合并或复制其外部模型路径。

当前选择本地规则提供器：不需要密钥即可完整走过身份核对、工具执行、资料引用与追问；外部 LLM、向量和重排仍是后续能力，不能把接口存在当成已实现。所有引用只证明资料定位，不证明实车根因。原始全阶段目标尚未全部完成。

## 2026-10-28：缓存、分页和写入权限均限定可信宿主

每个工作流独立创建注册表，缓存和游标绑定任务；读缓存不跨任务共享。写入与危险工具必须有角色权限、确认和审计；审计启动失败不执行，状态不确定时不重试。当前 HTTP 仅暴露固定只读流程，客户端不能指定角色或确认。备选向浏览器暴露任意工具执行接口风险更高且无当前需求，不采用。

## 2026-10-28：评测使用公开可复查的定位标签

固定 60 条真实已核验资料标题与目标条目，作为定位回归；标题查询具有词面优势，结果不宣传为口语查询或故障诊断准确率。根因命中、引用语义支撑和幻觉率需要独立人工真值，保持未评测。阈值写入配置，指标和逐条结果同时输出；公开源码不记录访客问题和私人诊断日志。
