## 0. 大白话一句话

**不用换拖拉机，加一套我们做的传感器 + 小盒子 + 屏幕，普通拖拉机就变成数字化的拖拉机了：哪儿发热、哪儿震得不对、油压低不低、电瓶行不行，屏幕上实时看得到，云上的司稼还能马上告诉你是什么毛病、现在能不能继续干、该什么时候修。**

这就是本方案的核心卖点，不是“又做了一个聊天机器人”，而是**低成本 retrofit（加装改造）套件**：老机器 + 传感器 + Agent = 数字孪生运维。

闭环一句话：**不同位置的传感器采数据 → 传到小盒子/云上 → 司稼诊断 → 屏幕+语音反馈给机手 → 机手处理/修完 → 传感器再采，验证好了没有。**

## 1. 总体架构：1 个中枢 + 3 个传感节点 + 云

```
拖拉机不同位置的传感器模块
├─ 节点 A · 发动机节点（发动机舱）
├─ 节点 B · 传动/液压节点（变速箱、液压油路、PTO）
└─ 节点 C · 电气/环境节点（电瓶、驾驶室、整车位置）
│ ESP-NOW（无路由器，250 字节小包，低延迟）
▼
中枢 Hub：ESP32-S3-N16R8（已买）+ 3.2 寸屏 + 0.96 寸 OLED
本地：特征计算、阈值告警、屏幕显示、语音播报
│ WiFi → HTTPS POST（手机热点演示）
▼
云：agridx.xyz —— 遥测入库 + 规则/物理诊断 + DeepSeek Agent 诊断
│ 诊断、置信度、维修建议、保养窗口
▼
反馈：中枢屏幕 + 语音 + 网页监控页（同一份结果，三处一致）
```

为什么分节点，不把所有传感器都直接插到中枢上：

1. **线不够长也不够稳。** I2C/SPI 是短距离总线，拖拉机上发动机到驾驶室几米，信号会衰减、受干扰。每个位置就地采、就地算特征，再用无线发特征值，才稳。
2. **地址会撞。** 很多便宜模块 I2C 地址是固定的，两个 ADXL345 直接并联没法区分。一个 TCA9548A 可分出 8 路 I2C 分支，解决同地址问题，但线长了还是不如分节点干净。
3. **坏一路不拖垮全部。** 某节点掉线，中枢标“该节点离线”，其他节点照常工作；全插一根总线上一路短路可能全挂。

**分期做法（保 12 月交作品）：**
- **P0 必做（台架 + 演示）：** 节点 A + 节点 B 的核心传感器，用有线先在台架上跑通，再改 ESP-NOW 无线。中枢只接 WiFi 上云。
- **P1 争取：** 节点 C（电气/环境/GPS）全上。
- **P2 规划：** 移动底盘、更多节点，不堵 P0。

## 2. 拖拉机不同位置 × 传感器 × 采什么 × 能发现什么

这是评委最想看的一张表：每个传感器不是“为了多而多”，而是对应一个部位、一种故障。

| 位置 | 传感器模块（单独模块） | 采什么信号 | 能发现的典型问题 |
|---|---|---|---|
| 发动机缸体/轴承座 | **ADXL345 振动 ×1** | 三轴加速度，1 kHz 采样，RMS/峰值/峭度/FFT 峰 | 不平衡（1× 转频峰）、松动（2× 峰）、轴承外圈/内圈故障（BPFO/BPFI 峰） |
| 发动机 | **DS18B20 防水温度 ×1** | 冷却液温度，-55~+125°C，1-Wire | 水温高、节温器/水泵异常、散热不良 |
| 发动机 | **DS18B20 防水温度 ×1** | 机油温度 | 机油过热、润滑失效前兆 |
| 发动机 | **INMP441 麦克风 ×1（已买）** | 声音 RMS、频谱质心 | 异响、敲缸、皮带打滑（与振动互相印证） |
| 发动机曲轴/飞轮 | **A3144 霍尔转速 ×1** | 脉冲计数 → 转速 RPM | 转速是算 1×、BPFO/BPFI 的基准，没有转速，频谱峰对不上故障；还能发现转速波动、熄火 |
| 变速箱壳体 | **ADXL345 振动 ×1** | 同上，第二测点 | 齿轮/轴承故障定位：发动机震、变速箱不震 → 问题在发动机；反之在变速箱 |
| 变速箱/液压油箱 | **DS18B20 防水温度 ×1** | 液压油/齿轮油温度 | 油温过高、油液老化、散热问题 |
| 液压油路 | **油压传感器 0–1.2 MPa，0–5V 输出 ×1** | 油压模拟量，经 ADS1115 读 | 油压低 → 提升无力/缓慢、泵磨损、滤芯堵；油压波动 → 内泄 |
| PTO 输出轴轴承座 | **ADXL345 振动 ×1（P1）** | 同上，第三测点 | PTO 轴承故障、农具连接偏心 |
| 电瓶/启动电路 | **INA219 电压电流 ×1** | 电压 0–26V、电流、功率，I2C | 电瓶亏电、充电系统故障、启动电流异常（启动困难的硬证据） |
| 驾驶室 | **BME280 温湿度气压 ×1** | 环境温度/湿度/气压，-40~+85°C、0~100% RH、300~1100 hPa | 作业环境记录、驾驶室高温告警、结合天气判断是否宜作业 |
| 整车 | **NEO-6M GPS ×1（P1）** | 经纬度、速度、时间 | 位置漂移、作业面积/轨迹、结合海报里的位置漂移场景 |
| 排气管附近 | **MQ-135 / 烟雾传感器 ×1（P2，可选）** | 烟气/有害气体浓度 | 燃烧不完全、冒黑烟（先做台架定性，不做定量标定承诺） |
| 油箱 | **浮子油位 / 超声波 ×1（P2）** | 油位 | 油量低告警、油耗异常（需标定，不做首期） |

**P0 必买（先下单）：** ADXL345 ×2、DS18B20 防水 ×3、A3144 霍尔 ×1、油压传感器 ×1、INA219 ×1、BME280 ×1。
**P1 争取：** ADXL345 ×1（PTO）、NEO-6M GPS ×1。
**P2 不买先写进规划：** 烟雾、油位。

> 选型教训（已查实）：**不要用 MPU6050 做轴承振动。** 它的默认低通带宽只有 260 Hz，在轴承故障分类实验里 held-out 精度掉到约 10%（随机猜水平）。ADXL345 量程 ±2/±4/±8/±16g 可选、13 位、输出速率 10–3200 Hz，才是振动主传感器。MPU6050 只适合做车身姿态/倾斜（P2），不做振动诊断。

## 4. 接线与总线（先看冲突，再接线）

### 4.1 中枢 Hub（ESP32-S3，已买）——不动原方案的屏和语音

- 屏 SPI：MOSI 11 / MISO 13 / SCK 12，CS 10、DC 9、RST 14、BL 21（原方案 §2.2，以到货引脚图核对）。
- 触摸：CS 15、IRQ 16。
- I2S 语音：BCLK 17、WS 18、INMP441 SD 38、MAX98357A DIN 37（建议值，核对引脚图；麦克风与功放可共用 BCLK/WS）。
- **主 I2C 总线：SDA 5、SCL 6**（注意：原方案 §2.3 给 OLED 建议的 8/9 与屏 DC 9 冲突，本方案改到 5/6；OLED 0.96 寸与 BME280、INA219、TCA9548A 都挂这条总线，地址不同不冲突：OLED 0x3C、BME280 0x76/0x77、INA219 0x40、TCA9548A 0x70）。
- **DS18B20 1-Wire：GPIO 4**，多探头共用一根线，靠 ROM 码区分，4.7 kΩ 上拉到 3.3V（不要拉到 5V，ESP32 引脚不耐 5V）。
- **ADS1115：挂主 I2C，地址 0x48**（ADDR 脚可改 0x48–0x4B，最多 4 个），油压等模拟量走它，不走 ESP32 自带 ADC。

### 4.2 节点（ESP32-C3 SuperMini，每节点一块小板）

| 节点 | 传感器 | 接法 |
|---|---|---|
| A 发动机节点 | ADXL345（SPI，CS 独立）、DS18B20 ×2（1-Wire）、INMP441（I2S）、A3144 霍尔（GPIO 中断计数） | 传感器就近装在发动机上，节点板用 5V 供电（18650 模块分路或 12V 转 5V），板子做防水小盒 |
| B 传动/液压节点 | ADXL345（SPI）、DS18B20 ×1、油压传感器（经本节点 ADS1115 或分压进 ADC） | 同上，装变速箱/液压油路旁 |
| C 电气/环境节点（P1，可并入 Hub） | INA219、BME280、NEO-6M GPS（UART） | 可直接挂 Hub，省一块节点板；GPS 天线朝天，别放金属盒里 |

**ADXL345 多个怎么办：** I2C 只有一个地址（ALT 脚可改到 0x1D，最多 2 个），所以振动节点用 **SPI**，每个 ADXL345 独占一个 CS 脚，共用 MOSI/MISO/SCK；或者走 TCA9548A 每路挂一个。**本方案选 SPI，采样率有保障。**

### 4.3 节点 → 中枢：ESP-NOW

- ESP-NOW 是 Espressif 的点对点协议，**不用路由器、不用连 WiFi**，节点不用上网，只把小包发给中枢；只有中枢连 WiFi 上云。节点可以电池供电、间歇工作，功耗远低于一直连 WiFi。
- 单包上限 250 字节，所以节点**不发原始波形，只发特征值**（见 §5），一个包完全装得下。
- 空旷距离约 200 m，拖拉机上几米完全够用；金属遮挡多就把节点天线露出来，别全包进铁盒。
- 中枢与节点约好同一 WiFi 信道（ESP-NOW 与 WiFi 共用射频，信道不一致会收不到，先在固件里写死信道，例如 1 或 6）。
- 掉线处理：节点每 2 秒发一次心跳+特征，中枢 10 秒没收到某节点就标“该节点离线”，屏幕和云上都如实显示，不编数。

## 5. 边缘算法：节点上算什么，中枢上算什么

### 5.1 采样（节点上，实时）

- **振动 ADXL345：** 量程 ±8g，输出速率 1600 Hz，实际采样 1000 Hz，窗口 1024 点（约 1 秒），Hamming 窗，1024 点 FFT，频率分辨率约 0.98 Hz。已有开源做法就是 ESP32 + 加速度计在 1 kHz 下做 RMS + FFT，再用阈值/异常检测，我们用更好的 ADXL345 照做。
- **温度 DS18B20：** 12 位，每 1 秒读一次，取 3 次中值滤波。
- **声音 INMP441：** 每 1 秒算 RMS（dBFS）和过零率，不录音、不上传音频（隐私 + 带宽）。
- **转速 A3144：** GPIO 中断计数，1 秒窗口算 RPM。磁铁 1 个/转，RPM = 脉冲数 × 60。
- **油压/电压电流：** 每 0.5 秒读一次，取平均。

### 5.2 特征（节点上算完再发，只发特征，不发波形）

每个振动窗口算：

| 特征 | 含义 |
|---|---|
| RMS、峰值、峰值因子 | 振动烈度，整体变大 = 有问题 |
| 峭度（Kurtosis） | 早期轴承故障最敏感：冲击多了峭度先升，RMS 还没动 |
| 1× 转频幅值、2× 幅值 | 1× 大 = 不平衡，2× 大 = 松动/不对中 |
| BPFO、 BPFI 幅值 | 轴承外圈/内圈特征频率处的能量，公式见下 |
| 主峰频率 + 幅值 | 频谱里最大的峰在哪 |

轴承特征频率公式（n=滚动体数，fr=轴频，d=滚动体直径，D=节圆直径，φ=接触角）：
`BPFO = n·fr/2 · (1 − d/D·cosφ)`，`BPFI = n·fr/2 · (1 + d/D·cosφ)`。
**固件里要先填轴承型号的参数**（例如台架 6204：n=8，d/D 查手册，φ≈0），没有参数就只报 1×/2×/峭度，不编 BPFO 数值。

### 5.3 阈值（先标定，再报警，不拍脑袋定死数）

开机先跑 **30 秒健康基线标定**（机器空转平稳时），记 RMS0、峭度0、各频点幅值0。之后：

| 等级 | 条件（任一满足） | 屏幕颜色 |
|---|---|---|
| 正常 | RMS < 1.5×RMS0，且峭度 < 4，且温度/油压在正常带 | 绿 |
| 注意 | RMS 1.5–2.5×，或峭度 4–6，或水温 > 90°C，或油压偏低 10% | 黄 |
| 告警 | RMS > 2.5×，或峭度 > 6，或 BPFO/BPFI 峰 > 3×基线，或水温 > 95°C，或油压 < 下限 | 红 |
| 传感器离线 | 10 秒无数据 | 灰，标“离线” |

阈值是相对基线的，换台机器、换个安装位置都要重新标定，参赛材料里要写“阈值来自本台架标定”，不写成通用国标值。

### 5.4 中枢融合（一句话规则）

单信号报警可能是误报，**两个及以上独立信号同时指向同一部位才升一级**。例如：发动机振动 RMS 升 + 声音 RMS 升 + 机油温度升 → 发动机问题可信度高；只有振动升、温度声音都不动 → 先标“注意，待复核”，不直接报故障。这就是“多传感器互相印证”，是本方案比单传感器强的点，写进材料里。

## 6. 上传：发什么、多久发一次、发不上去怎么办

### 6.1 节点 → 中枢（ESP-NOW，每 2 秒一包，结构体，不是字符串）

```c
typedef struct {
uint8_t nodeId; // 1=发动机, 2=传动/液压, 3=电气/环境
uint32_t ts; // 节点毫秒时间
float vibRms, vibPeak, kurtosis;
float f1x, f2x, bpfo, bpfi; // 幅值，单位 g
float tempC; // 本节点主温度
float rpm; // 节点 A 有，别的节点填 -1
float extra; // 节点 B: 油压 MPa；节点 C: 电压 V
uint8_t level; // 0 正常 1 注意 2 告警
} NodePacket; // 约 40 字节，远小于 250 字节上限
```

### 6.2 中枢 → 云（HTTPS POST，每 5 秒一次 + 告警立即补发）

**首选 Plan A（新增采集接口，小改动）：** 新增 `POST /api/telemetry/ingest`，中枢把三节点特征 + 时间戳 + 设备号一起发，云端入库，监控页从“模拟数据”切到“真实数据”。请求体示例：

```json
{
"deviceId": "siji-robot-01",
"source": "real",
"ts": "2026-11-20T10:00:00+08:00",
"nodes": [
{"nodeId": 1, "place": "engine", "vibRms": 0.42, "vibPeak": 1.8, "kurtosis": 3.2,
"f1x": 0.12, "f2x": 0.05, "bpfo": 0.03, "bpfi": 0.02, "tempC": 82.5, "rpm": 1500, "level": 0},
{"nodeId": 2, "place": "gearbox", "vibRms": 0.31, "tempC": 68.0, "oilPressureMPa": 1.05, "level": 0}
],
"batteryV": 13.8, "batteryA": 2.1
}
```

云端只存特征值，不存原始波形（除非告警时节点补发一个窗口的原始采样做复核，限 1 次/分钟）。

**保底 Plan B（零服务端改动，先跑通演示）：** 不等新接口，中枢把特征值拼成一句话调已有接口 `POST /api/chat`（已实测通，不带 Origin，约 18 秒返回）：
`"发动机振动 RMS 0.42g（基线 0.18g，2.3 倍），峭度 5.8，水温 96°C，转速 1500rpm，请诊断最可能原因和处理建议。"`
云上 Agent 照常回答，屏幕显示答案。**先按 Plan B 跑通全链路，再做 Plan A，Plan A 做不完也不影响演示。**

断网处理：中枢本地缓存最近 100 条特征（PSRAM 里），断网照常显示本地实时值并标“离线，本地数据”；恢复后补传，不编时间戳。

## 7. 云上反馈检测：怎么从一堆数变成一句话诊断

1. **规则层（快，本地+云上都跑）：** §5.3 的阈值先判等级，秒级出“注意/告警”。
2. **物理层（可解释）：** 按转速算 1×/2×/BPFO/BPFI，看哪个频点超了 → 定位到不平衡/松动/外圈/内圈。这是跟纯 LLM 的区别：频率是算出来的，不是猜出来的。
3. **Agent 层（给建议）：** 把特征值 + 规则结论 + 物理定位一起喂给司稼（DeepSeek），结合知识库 13,236 条 + 知识图谱，输出：最可能原因（1–2 个）、置信度、能不能继续干、检查步骤（按顺序 3–5 步）、建议维修窗口（结合海报的“非作业窗口维修”思路）。
4. **低置信度要认：** 特征互相矛盾、或数值在边界上，Agent 必须说“目前证据不足，建议先做 X 检查再定”，不硬给结论。这是之前知识库整理里定的“无匹配 → 回答未知并追问”原则，诊断里同样适用。
5. **反馈回路（闭环的最后一环）：** 诊断结果同时写回三处——中枢 3.2 寸屏（大字结论 + 置信度条）、0.96 寸 OLED（状态行：正常/注意/告警 + 关键值）、网页监控页（曲线 + 告警列表 + 诊断卡片）。机手按建议处理（例如停机紧固、加油、降负荷），传感器下一轮采样就能看到 RMS/温度回落，屏幕上从红变黄变绿，**这就是“反馈检测”的现场证据**，演示时要拍下来。

## 9. 台架验证：没有真拖拉机，先在台架上证明闭环是真的

**台架（用电机模拟旋转机械，别等真拖拉机）：** 12V 775 电机 + 联轴器 + 6204 轴承座，ADXL345 用螺丝刚性固定在轴承座上，DS18B20 贴在轴承座/电机壳上，A3144 对着轴上小磁铁，INMP441 距离 10 cm。

| 工况 | 做法 | 预期信号 | 采多久 |
|---|---|---|---|
| 健康基线 | 空转平稳，螺丝紧固 | RMS0、峭度 ~3、1× 小 | 30 秒 ×3 次 |
| 不平衡 | 轴上加 2g 偏心螺丝 | 1× 幅值明显升，RMS 升 | 30 秒 ×3 次 |
| 松动 | 轴承座固定螺丝松 1/4 圈 | 2× 幅值升，RMS 升 | 30 秒 ×3 次 |
| 轴承外圈故障 | 换一个旧/有损伤的 6204（有就做，没有就不做，不编） | BPFO 峰升 | 30 秒 ×3 次 |
| 水温高 | DS18B20 放温水杯 40→85°C | 温度曲线升，>90°C 注意、>95°C 告警 | 全程记录 |
| 油压低 | 油压传感器接气压/水压模拟（或台架上调阀门） | 油压值降，告警 | 全程记录 |

**要记的数（参赛材料用，待验证后填写）：** 每种工况的检出率（3 次里几次报对）、健康工况的误报次数、从信号超阈值到屏幕变红的时间、从上传到云诊断返回的时间。**不要只写“效果很好”，要写“不平衡 3/3 检出，健康 0 误报，本地告警 <2 秒，云诊断约 18 秒”这种可核对的数。** 做不出来的工况如实写“未验证”，不编。

## 13. 参赛讲法（三句话，写进申报书）

1. **改造，不是造新机：** 一套两三百元的加装套件，让普通拖拉机变成数字化、可实时监测的拖拉机，老机器也能用，推广门槛低。
2. **多点、多信号、互相印证：** 发动机、变速箱、液压、电气不同位置各放传感器，振动+温度+声音+转速+油压+电压一起看，两个信号同时指向同一部位才升一级，比单传感器误报少。
3. **边缘算特征、云上做诊断、现场看反馈：** 节点上算 RMS/FFT/峭度/BPFO 只传特征，云上 Agent 给原因+置信度+维修窗口，处理完传感器马上能看到指标回落，形成“监测—诊断—处理—再监测”的闭环。
