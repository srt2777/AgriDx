此版针对 S3 实机修复，不以 C3/OLED 的旧说明作为验收依据。README、`ASSEMBLY.md`、`FLASHING.md`、`VOICE.md` 中原 RV0.1.0 的首页、轮询、待机、字库及旧 OTA 描述属于历史设计；与本次修复冲突时，以本文和当前源码为准。

### INMP441 接线

断电后接线，麦克风使用 3.3V。当前配置启用 `VOICE_I2S_USE_ALT_PINS=1`。

| INMP441 引脚 | ESP32-S3 |
|---|---|
| VDD / VCC | 3V3 |
| GND | GND |
| SCK / BCLK | GPIO17 |
| WS / LRCLK | GPIO18 |
| SD | GPIO4 |
| L/R | GND（左声道） |

GPIO19/20 保留给原生 USB，不接麦克风数据线。GPIO47 是代码中的功放数据输出预留，本机没有功放/扬声器，不需要接线。相关配置见 [`include/display_config.h`](../include/display_config.h)。

## 2. 中文与卡顿修复

- 启用 LVGL 压缩字库支持，解决压缩字体存在但渲染配置不匹配的问题。16px 字库扩充为 ASCII、`U+4E00–U+9FEF` 基本汉字及界面所需符号，用于回答和 Wi-Fi 名称；12px、22px 保留界面子集。这里的完整 16px 字库不包含所有 Unicode 汉字扩展区或 emoji。
- 校正 LVGL 时钟，使用实际毫秒时间；调整 S3 的 LVGL 内存、PSRAM 使用与内部 DMA 绘图缓冲，避免把绘图缓冲的分配位置与 DMA 能力混淆。
- S3 显示总线设为 40MHz，切页使用无过渡动画的即时切换，减少全屏动画重绘；卡片去掉阴影，保留圆角与边框。
- 保持监测常亮，关闭自动进入待机动画；数据持续显示，断流状态明确提示。

40MHz 的稳定性仍取决于屏幕模组、接线与供电，第二版实机验收需要确认没有花屏或触摸异常；编译通过不能替代这项验证。

## 3. 三页界面与告警

界面采用正式站旧版蓝白工作台样式，标题为“司稼 · 智能运维”。保留小屏实际需要的功能，不加入网站导航、知识条目或演示通道入口。

| 页面 | 当前行为 |
|---|---|
| 监测 | 水温、油压、转速三张数值卡与趋势图；常驻“模拟数据”标记；初始未收到有效样本时显示“等待数据” |
| 对话 | 预设问题、按住说话、回答及来源证据、新对话；来源信息保留，不因小屏适配被删除 |
| 联网 | 异步扫描附近 Wi-Fi，按信号强度排列，SSID 去重，最多显示 12 项；点选加密网络后输入密码并连接，开放网络可直接连接 |

联网输入层使用屏幕英文键盘，可切换大小写、数字与符号；密码遮罩显示。连接请求由主程序保存至 NVS 并交给网络任务处理，界面扫描不等待阻塞 LVGL。此页不是中文聊天键盘，也没有另开 HTTP 配网页面。

告警沿用服务器提供的通道状态和阈值，不在屏幕代码中另加阈值。通道进入“注意”或“报警”、或严重程度升级时弹窗，展示通道、当前值、单位与“模拟数据”；同一等级连续刷新不重复弹出，恢复正常后可再次触发。用户可关闭弹窗，也可转入诊断，问题中保留模拟数据来源。正常且已有有效数据时显示“暂无告警”。

## 4. 模拟遥测与对话边界

当前监测接入网站现有 `GET /api/telemetry/stream` SSE 模拟流，**不是实际农机传感器读数**。识别 `catalog`、`telemetry`、`reset` 事件，接收服务器给定的通道量程和阈值；对数据来源、通道完整性、数值及时间顺序作检查，保留有界趋势历史。断流重连有退避，断网或超过 5 秒没有新鲜样本时标记数据过期，不把旧值当成仍在更新的数据。

网络任务解析数据，主循环消费结果并更新 LVGL；网络线程不直接操作界面。实现见 [`src/telemetry_stream.cpp`](../src/telemetry_stream.cpp) 与 [`include/telemetry_protocol.h`](../include/telemetry_protocol.h)。

文字对话仍使用网站 `/api/chat`，保留对话历史和来源证据。麦克风录音使用 `/api/voice/ask`：当前语音服务接收单次原始音频请求，不携带完整多轮会话上下文，因此不能声称与网站文字多轮对话完全等同。语音识别文字和答案可以显示在小屏，并进入本地对话记录；后续文字追问可使用这些记录。

`VOICE_PLAYBACK_ENABLED=0`：本机没有扬声器，收到语音结果后显示文字，不下载或空播 TTS。麦克风未接、静音录音和真实说话识别的最终板端表现仍需逐项验证。

## 5. 无线升级

旧的联网自动拉取版本文件、自动下载固件路径已通过 `ENABLE_OTA=0` 关闭。本次新增独立的密码保护 ArduinoOTA 模块，见 [`src/local_console.cpp`](../src/local_console.cpp)。

- NVS 未配置有效独立密码摘要时，OTA 默认关闭，不创建无密码升级监听。
- 首次通过 USB 串口发送 `OTAPASS <独立随机密码>` 配置；尖括号部分是占位说明，不是实际密码。密码须为 16–128 个可打印 ASCII 字符，避免复用 Wi-Fi 或网站密码。
- 只在已有 Wi-Fi 的 STA 模式联网后提供升级，主机名为 `sijia-robot`，端口为 3232；不创建 AP。断网或接口变化时更新监听状态。
- NVS 保存 SHA-256 摘要，固件只输出配置成功/失败，不打印密码或摘要。`STATUS` 可查看当前 IP 与 OTA 启用状态。
- 上传工具应使用当前 Arduino-ESP32 框架随附的 `tools/espota.py`，与此版 ArduinoOTA 的认证实现匹配；成功上传后重启。

本记录不保存任何 Wi-Fi 密码、OTA 密码、API 密钥或其他凭据。模块和配置检查通过不等于已完成无线升级实测；密码配置与真正无线更新结果留待验收补记。

## 最终校正：坐标轴、指标切换与对话空白

用户再次澄清纵轴需要放大变化、横向走势保持平滑；另一聊天经用户授权转来同一要求及点击指标切换曲线。

- **最终横轴恢复60秒**，没有采用中途提出的30秒窗。水温纵轴最小8°C跨度，油压40kPa、转速400rpm；超出时自动扩大包含完整峰值。曲线用10倍定点值绘制，保留0.1精度，消除取整到1°C带来的台阶感，不对时间序列额外平滑或改写。
- 点击水温/油压/转速卡片，切换各自60点历史、名称、单位、量程及适用报警线；选中卡片蓝色突出。切换不修改数据更新时间或触发新的告警。
- 用户确认空白是在对话页“按住说话”上方，并非Wi-Fi键盘。消息列表改为内容高度，最大高度按同页按钮/状态栏的实际剩余空间计算；少量内容紧凑排列，长回复占满可用区域并纵向滚动。
- 板端定位：触摸读取约40–800微秒，SPI每5秒约100毫秒，而LVGL处理总耗时常超过2秒；仍有350–850毫秒单次处理峰值。LVGL96KB对象池移到内部RAM、TLS大块缓冲改为PSRAM后，TLS连接与诊断成功（一次诊断7.643秒），但绘制峰值未明显改善，**不能宣称流畅度已修复或达到60FPS**。UI内存实测约23–29KB，内部堆余量约61–70KB。
- 语音识别到连续诊断的新流程已固件实现；用户说稍后再试，麦克风端到端时延仍待验收。网站未部署，本次没有GitHub推送。
- 最终变更通过字库解码、真实SSE逐字节回放、三通道增强趋势/故障恢复ASan/UBSan检查及S3构建。

最终USB烧录已完成，写入哈希校验通过。发布文件 `release/sijia-s3-display-repair-0.1.1.bin` SHA-256：`ea51e0a926f3ec5d98d1772f66eb6c69190b2973ec60957b6a58747114313b87`。重新枚举后串口从 `usbserial-110` 变为同型号CH340的 `usbserial-120`；没有更改网络出口。

## 11 月 12 日 USB 与 OTA 复测

- S3 使用内部 RAM 的局部 DMA 双缓冲、40 MHz SPI 和 `-O2`，避免把不变样式写回 LVGL。USB 写入 4,576,128 字节，校验通过，写入耗时 49.5 秒。
- 轮辐改用车轮内的局部坐标，待机动画稳定窗口的 LVGL 处理峰值为 50–55 ms。独立实验在同一板上各跑三轮 120 帧，RGB565 SIMD 关闭和打开时的中位耗时为 76.90 和 77.47 ms/帧，未见收益。候选固件使用 LVGL 通用渲染。触摸读取的串口计时不代表手指到屏幕响应。
- 原始 NVS 读回发现部分记录末字重复。新校准记录在现有命名空间写入镜像数值，写后核对并校验，成功后切换活动记录，仍可读取旧校准。两组不同参数均经 USB 写入和重启读回，最后恢复原参数。
- 局域网 OTA 用密码认证，传输中暂时关闭 Wi-Fi 省电并分段让出处理器。上传端连续发送并并行读取回执，以设备最终校验确认完成。第一轮 47.86 秒完成传输和校验，含认证 52.95 秒，设备从 app1 启动，仍能读取校准并接收 SSE。第二轮传输和校验 46.25 秒，含认证 47.34 秒，切回 app0 后校准与 SSE 正常。错误密码在传输前被拒绝。Mac 上另一个 Python 解释器的一次 TCP 回连超时，使用系统 Python 完成两次成功传输。
- 正式站语音基线以合成普通话音频测得 47.46 秒后返回 502。本地服务端复用 faster-whisper 进程后，真实模型的 HTTP 首次识别 911 ms，后续 292–312 ms。语音测试 23 项通过。短句中的“拖拉机”仍有误识别，且正式站服务与板载麦克风端到端耗时尚未复测。

在同一局域网，先通过 USB 配置独立的 OTA 密码，再从电脑运行下列命令。程序会在终端中提示输入密码。macOS 实测使用系统 Python 接收设备的 TCP 回连。

```sh
/usr/bin/python3 tools/ota_upload.py \
  --espota /path/to/arduino-esp32/tools/espota.py \
  --device <设备IPv4> --host <电脑IPv4> \
  release/sijia-s3-display-repair-0.1.1.bin
```

升级重启后使用 USB 串口的 `STATUS` 核对活动分区。后续如果手动烧录应用，按实际目标选择 `app0`（0x10000）或 `app1`（0x650000），保留 NVS 和分区表。

## 整体刷新与硬件扩展试验

S3 快速渲染使用 PSRAM 背景缓存、局部重绘与 DMA 双缓冲。LVGL 可在 SPI 发送上一块像素时绘制下一块，在触摸读取前结束最后一次 SPI 事务。待机更新周期从 40 ms 改为 32 ms，SPI 保持实测过的 40 MHz。快慢设置分别重启测试，按实际传送像素的刷新计数，排除刚进入场景的窗口。

| 待机画面 | 两个稳态窗口 | 帧耗时峰值 |
|---|---|---|
| 原设置 | 22.2、22.8 FPS | 50.6–51.0 ms |
| 新设置 | 26.2、29.1 FPS | 37.7–46.7 ms |

新版经 USB 写入及哈希校验，监测、对话、联网页切换后串口仍正常，Wi-Fi、SSE 与原校准可用。上述帧率为待机场景，不是面板扫描频率。

- Wi-Fi OTA 此版实测完整 4,583,392 字节，45.75 秒传输与校验（97.8 KiB/s），含认证 46.88 秒。设备切到 app1，校准和 SSE 均正常。隔离的 BLE 5 测试协商到 2M PHY，512 KiB 固件片段传输 50.86 秒，设备端 SHA-256 一致，约 10.1 KiB/s。BLE 测试未写入 OTA 分区。整包升级继续走 Wi-Fi。BLE 可用于手机配网和读取短状态。
- 屏幕上的 SD 卡槽尚未接线或插卡。可用第二组 SPI 连接卡槽，建议先做掉线历史缓存、故障 CSV 导出，再评估存放签名升级包。保留现有闪存双 OTA 分区。卡槽读写尚未实测。
- 板端 ESP-SR VadNet 用合成普通话音频与前后静音完成实机试验，164 个 32 ms 音频块的平均推理耗时 2.87 ms，峰值 4.37 ms，开头静音无误触发。独立试验占用约 23 KB 内部堆，模型包约 288 KB。后续可在录音时识别有效语音，保留上下文后再上传，需用真实麦克风和农机噪声验证。现有 SDK 包的命令词模型为英文，中文命令词需要另外准备模型。
