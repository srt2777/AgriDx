# 改动计划模板

> 复制后替换所有占位符；本模板不加入 `sources.json` 或 `entries.jsonl`，不参与检索。
> 流程见 [docs/knowledge-governance.md](../docs/knowledge-governance.md)。
> 每批新增先出改动计划，人审通过后再写库；未通过校验不合并。
> 填表原则：不知道的写“待核实”，不编造来源、页码、型号、配置或参数。

## 去重依据

每条新增 / 修改 / 取代的疑似重复对都要有一行；无疑似重复的写“无疑似重复，已比对”。

| pair_id | 条目 A | 条目 B | 相似度 /  tier | decision（keep / supersede） | 理由（先看适用范围再看文字） | 判定人 / 日期 |
| --- | --- | --- | --- | --- | --- | --- |
| DP-… | KB-… | KB-… |  |  |  |  |

去重口径：同一知识在不同机型 / 不同手册范围内的变体分别保留（`keep`），不判重复；
只有同一事实、适用范围实质相同、且较新来源已覆盖较旧来源时才判 `supersede`。
判定写入 `dedup-review.jsonl`，AI 建议只供参考，不代替人判。

## 合并方式（新内容如何进已有知识卡，不覆盖旧条目）

- 新增事实追加新的 `## 条目编号｜标题` 段；旧段原文不动、不改写、不删节；旧 `entry_id` 不复用。
- 被取代的旧条目：在旧知识卡段后追加取代说明（被哪个 `entry_id` 取代、依据哪个 `pair_id`、
  判定日期），旧段正文保留可查；新条目卡段追加一行“取代说明”。
- 同一机型的相近事实分别保留，各自标明适用条件，不“合并成一条”。

## 回滚办法（写到不看人也能执行）

1. **删哪些索引行**：
   - `entries.jsonl` 新增行（entry_id）： 
   - `sources.json` 新增来源（source_id）： 
   - `hierarchy.json` 新增行（entry_id + 组件 / 零件）： 
2. **恢复哪个文件版本**：
   - 被改的旧条目行恢复到提交 SHA： 
   - 被改的知识卡段恢复到提交 SHA： 
   - 被改的 `hierarchy.json` 行恢复到提交 SHA： 
   - `kb-version.json`（`kb_version` 与 `content_hash`）恢复到提交 SHA： 
3. **执行方式**：首选 `git revert <该批提交 SHA>`；若其后已有后续提交压上，改用反向改动计划逐项恢复，
   再重算 `kb-version.json`。禁止用 `force-push` 改写已合入 `main` 的历史。
4. **回滚后验证**：重跑 `python3 知识库/工具/校验索引.py` + `npm test` + `npm run build:server` +
   `npm run verify`，并核对 `/api/health` 的 `archivedEntries` 等于 `entries.jsonl` 行数。
