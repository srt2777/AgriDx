# 固定的资料整理与检索规范

本规范用于本轮和后续新增。目标是让GitHub读者和AI使用同一份可追溯事实，明确哪些内容已核对、哪些只是线索。

## 国内使用机型的采集顺序

先核对国内使用证据，再建立型号候选，随后查找精确适用的手册。国内使用的进口品牌同样适用，不以企业注册地推断购机地域，也不限定现有品牌。

1. **核对统计与报道**：优先农业农村部门的实际统计、购机公示和应用报道；其他可信新闻或行业分析保留实际作者和来源等级。阅读实际正文，保留网址、发布日期、观测期、取得日期、地域覆盖、单位、统计对象、申请/审核/兑付状态及去重方法。未披露的字段写未知；未取得正文时仅保留请求状态，不从搜索摘要补造事实。
2. **建立有依据的型号候选**：每条型号证据指向明确来源，记录原文名称、数值或定性表述及限制。同型号在多篇报道中出现时保留各条证据，候选清单按有依据的品牌和型号去重。报道可能省略完整后缀，称“报告所列型号”，不自动补排放、年款或配置。人工确定的搜索次序写清理由，不当作全国使用量排名。
3. **定向寻找手册**：从真实厂家、可信经销商或资料栏目链接找整机使用/维护说明书。分开记录产品页、手册目录、培训、视频、下载失败和取得正文的状态。候选目录不能计为已取得PDF；未取得结论只限本轮已检查入口，不说明全网不存在。
4. **匹配与核验**：取得手册后独立核对封面、正文型号、后缀、市场/排放、发动机、变速、配置、序列号及版次。近似型号不得互换；中文或某地区目录不自动证明国内适用。完成文件完整性检查，再对拟整理的证据选页目视核验，保留已审范围。
5. **整理并接入**：经核验的手册按下文交付物和条目规则归档，完成索引和实际问答验收后接入维修检索。统计报道解释采集理由，不提供维修参数。

采集研究保存在[采集优先级目录](整理后的知识库/农用拖拉机知识库/采集优先级/README.md)。其中`README.md`供人阅读，`证据索引.json`维护来源与型号关联证据，`型号清单.jsonl`每行一个去重候选及搜索状态。保留原创来源记录、公开入口、响应哈希与字节数；临时抓取路径不当作长期链接。该目录不加入维修用`sources.json`、`entries.jsonl`或维修RAG，不能用研究候选数增加手册或维修条目数量。

| 证据类型 | 可以支持什么 | 必须保留的限制 |
| --- | --- | --- |
| 官方保有量统计 | 所述时间、地域、机类或型号范围内的存量 | 机类总量不分配给某品牌/型号；省县结果不扩展成全国 |
| 省县购机公示 | 特定公示范围、状态和时段的购机记录或汇总 | 申请、审核、兑付状态分开；查明重复/撤回及去重口径，不等同保有量 |
| 第三方补贴统计 | 作者所述的数据覆盖与统计结果，作为手册发现线索 | 不能升级为已独立核验的官方统计；原始公示未取得和口径未披露要注明 |
| 混合热度/关注指数 | 报告所述观测期的关注或求购线索 | 热度不是台数；归一化分组之间不能直接比较；发布年不替换观测年 |
| 宣传、鉴定或补贴准入 | 产品或目录候选入口 | 不证明实际购机量、使用量或适用维修参数；预测产销不是已实现数量 |
| 局部应用或交机报道 | 特定地点与项目中明确记载的实例或数量 | 试用、交付、场景数量分别记录，不相加重复实例，不外推全国普及程度 |

仅保存采集所需的汇总和型号证据，不归档个人受益者姓名、身份证、联系方式或具体住址。品牌总量不转移到主销型号，企业所在地不当作购机发生地。原文数量或口径冲突时并列记录待核实，不用自己的估计补齐。

## 一份资料的交付物

1. **原件或来源记录**：`原始农机说明书/品牌/型号或系列/`。保留原文件名；不同版本不覆盖。新外部原件未另行归档全文时，保存原创来源记录、公开链接和取得时的PDF完整性数据。
2. **来源索引**：统一`sources.json`一份资料一个`source_id`。同一PDF被多个机型页引用时去重，按封面及正文明确的型号范围登记。
3. **人读知识卡**：`整理后的知识库/农用拖拉机知识库/机型知识卡/`或配套系统目录。先写来源/版本/范围/已审程度，再按编号列事实、适用条件与证据。原有知识卡可沿用，不复制一份正文到服务端。
4. **机器条目索引**：`entries.jsonl`每行一个JSON对象，只保存定位、标签和适用元数据。编号对应知识卡确切段落，事实正文只在Markdown维护；不得用`summary`保存第二份事实概述，校验工具会拒绝该字段。
5. **导航与检索记录**：更新品牌表、数量、采集日志和待补清单；取得文件、内容核对及网站接入分别记录。找到但未读到正文的资料仍保留线索，不进入事实检索。

## 来源字段

| 字段 | 含义与规则 |
| --- | --- |
| `source_id` | 稳定且唯一；新版本原则上新编号，旧证据不改指到新原件 |
| `brand`, `model`, `models` | 品牌与文字范围；`models`列证据明确的精确型号/别名，不推断相近型号兼容 |
| `title`, `document_type`, `role` | 区分整机、维保、交机培训、配套系统、网页和报道；`title`为必填书名/网页标题，按封面或已存网页标题原文登记，不翻译、不补造 |
| `title_status`, `title_evidence` | `已核对`时须写明书名出处（如“封面PDF第1页”“已存HTML的<title>”）；无法核对时填`待核实`并保留有据候选，不得编造书名 |
| `brand`, `sub_brand`, `product_line`, `brand_label` | `brand`统一为主品牌（如雷沃、千寻位置）；子品牌（欧豹、阿波斯）写`sub_brand`，产品线（千耘）写`product_line`；`brand_label`保留原合并标签供追溯。条目`brand`须等于来源主品牌或其`brand_label`（既有条目保留原标签以维持历史批次字节基线），检索与目录统一按来源主品牌显示，旧标签筛选由服务端映射 |
| `model_ids` | 由`models`（缺省时`model`）机械派生的规范编号：去空白、全角括号转半角、其他符号转`-`、字母大写、保序去重；不新增型号或兼容关系，原`model`/`models`含义不变 |
| `path`, `url`, `download_url` | 仓库保留的原件/来源记录路径、公开入口及直链；不填临时目录作为长期路径 |
| `version`, `version_date` | 手册编号及纸面版次；日期冲突分别保留，网页上传时间不当出版日期 |
| `pdf_metadata_date` | 可选，仅存PDF元数据中的日期；不是出版或印刷日期，不能填入`version_date`冒充版次。独立版次日期未知时`version_date`可省略或为`null` |
| `scope_boundary`, `status` | 市场、配置、序列号、待核实条件及已审范围 |
| `sha256`, `bytes`, `pdf_pages` | 本地原件的完整性数据；来源记录模式的前两项属于记录文件，不是PDF |
| `storage_type` | 原件留存可省略；仅留链接及记录时使用`link_and_source_record` |
| `manual_sha256`, `manual_bytes`, `manual_pdf_pages` | 仅记录模式下实际取得PDF的完整性数据，与本地记录哈希分开 |
| `verified_pdf_pages` | 真正核对过的PDF物理页及内容；仅渲染但未阅读不当作已核对 |
| `emission_stage` | 可选，只有原件明确时填`国三`或`国四`；未知不猜测 |
| `emission_stage_unknown` | 可选布尔值；来源存在排放冲突或仍未知时填`true`，阻止仅由型号G4后缀推断阶段；不能与来源已明确的`emission_stage`同时成立 |
| `configuration` | 可选`CAB`或`ROPS`，仅在原件明确整册配置时填写；混合手册不统一填写 |
| `drive_configuration` | 可选`2WD`或`4WD`，仅在原件明确整册驱动范围时填写；混合手册不统一填写 |

记录原件发行、语言、来源等级及再分发边界。英文/海外版、辅助导航和无人整机不混用。传输长度一致、末页可解析只能证明文件完整，不等于全书事实核验。

## 条目字段

| 必填字段 | 规则 |
| --- | --- |
| `entry_id` | 稳定唯一，ASCII大写字母/数字/连字符；每次新增不可复用已有编号 |
| `source_id` | 必须存在于来源索引 |
| `brand`, `model`, `title` | 与证据相符；标题与Markdown编号段一致 |
| `knowledge_path` | 仓库内`整理后的知识库/`下的Markdown；不得指向原件、README或临时文件 |
| `locator` | 章节/表号、PDF物理页和实际印刷页；网页使用栏目/编号及来源快照 |
| `entry_type` | 使用下面的类别；不能把待取得资料标成维修事实 |
| `status` | 清楚记录文本/图像核对及未完成的厂家、实车、全书审校 |

可选`scope_boundary`或`use`补充条目自己的限制；可选`emission_stage`只限定该条目条件，不能把一页国三机油要求扩展成整册排放结论。来源限制和条目限制会一同送入回答。

配置专用条目可填`models`，必须是来源明确型号列表的非空、无重复子集；填入后覆盖来源的宽范围，只在用户精确型号匹配时检索，品牌或系列未定不能召回。不能凭型号后缀猜配置。例：LX2620驾驶室专用维护须依据原规格表填写`["LX2620HSDC", "LX2620HSDCC"]`，不使用包含SU的整册范围。未填写时沿用来源型号列表；市场、版本及其他配置条件仍需按正文核对。

条目可用`configuration`限定自身的`CAB`或`ROPS`条件，不与来源已定配置相冲突；未知或混合范围不填。问题明确提到CAB/驾驶室或ROPS/防翻架且与条目已定配置冲突时，排除该条目；单凭型号命中不能覆盖配置冲突。当前其他配置仍依赖文字边界，不将此字段描述为全部配置自动核验。

`drive_configuration`同样可用于条目；已明确两驱/四驱冲突时排除。比如M6060/M7060本册规格页明确4WD，使用该字段；M5手册同时覆盖2WD/4WD，不统一填写。只有具备原文证据的条件才设置；其他变速、附件、序列号和市场条件仍须核对文字范围。

### 可选角色与风险字段（2026-10-21）

为“品牌→型号→组件→零部件”导航下展示“运行故障表现→对应策略”，条目可增加以下可选字段。字段只标注本条Markdown正文已经写出的内容类型，不新增事实、不改变适用范围；旧条目不填写仍然有效。

| 字段 | 规则 |
| --- | --- |
| `roles` | 本条正文实际包含的角色，取`symptom`（故障表现/现象）、`cause`（候选原因）、`check`（检查/诊断步骤）、`action`（处理/维修策略）、`retest`（复检/恢复验收）的非空、无重复子集，并按此顺序排列 |
| `role_basis` | 填写`roles`时必填：`原文标记`表示正文有明确字段标签（如“故障现象：”“可能原因：”“诊断步骤：”“维修建议/针对处理：”），校验工具逐项检查标签存在；`人工核对`表示整理者对照知识卡与证据页人工判定 |
| `risk_level` | 可选`high`、`medium`、`low`，表示该现象/操作涉及的安全或损坏风险提示等级，不是故障确诊、维修难度或安全保证 |
| `risk_basis` | 填写`risk_level`时必填，写明依据，如原文警示所在段落或人工核对说明；不得只凭标题关键词定级 |

- 只有正文存在明确标记的条目才能自动标注`原文标记`；没有标记、表述含糊或需要判断的条目不自动填写，留待人工审核后以`人工核对`填写。宁可不填，不猜测。
- `资料索引`、`资料核验`、`机型资料`、`资料缺口`、`系统适用边界`不标注角色或风险。通识（TK）条目不在本索引，不能借此成为证据。
- 未标注表示尚未整理，既不表示没有该角色，也不表示低风险。服务端现有的检索派生覆盖与风险提示仍独立运行，不以本字段数量作为性能覆盖率。
- 校验工具在`summary.role_schema`中统计已标注角色与风险的条目数；服务端加载时同样检查字段结构，结构错误时拒绝加载新索引。

允许的类别：`维护/故障知识`、`操作/维护知识`、`安全操作`、`系统安装/调试`、`系统适用边界`、`资料索引`、`资料核验`、`机型资料`、`资料缺口`。后五类中的资料信息不展示为维修判断；配套系统边界也不当作整机维修依据。

## 正文和核对要求

- 使用`## 条目编号｜标题`。一个条目说明一个清楚问题，写事实与前提；相近现象必须区分，例如不转/转动无力、不能提升/下降缓慢。
- 保留表格行列对应关系和脚注。扫描页、数值表和故障表同时核对图像，引用正文实际页脚，不按目录推算。
- 参数只在机型、发动机、配置及版本明确时整理。条件不全或有冲突时保留待核实，不拼接其他机型数值；不从宣传页或视频标题生成操作流程。
- 服务端通用文档没有归档来源与精确适用元数据时，只保留信息收集问题和匹配手册的缺口提示，不提供候选故障原因、维修流程、参数或保养周期。取得证据的维修事实按知识卡及索引流程接入，不以通用示例或免责声明替代来源核验。
- 故障原因列为候选，不能直接确诊或建议盲目换件。整理者补充的限制应标明“整理边界”，不冒充厂家原句。
- 不全文翻录外部手册。保存可追溯链接和独立事实概述；既有用户原件保留原状。

## 分层资料导航

正式索引通过`整理后的知识库/农用拖拉机知识库/hierarchy.json`关联品牌—来源明确的型号/范围—组件—零件，细则见[分层导航规范](整理后的知识库/农用拖拉机知识库/分层导航规范.md)。该文件只维护条目编号、导航分类及文字核对词，不重复保存故障事实或处理策略。增删正式条目时同步维护导航关系，保留条目自己的精确型号子集和配置条件；未知零件只到组件，缺资料时保留待补。

组件及零件归属须人工核对原知识段及证据；名称出现只支持导航关联，不等同于坏件、确定因果或兼容性。资料信息、安全操作、维护与故障分别按原类别呈现，导航计数不当性能覆盖率。事实仍由原Markdown编号段提供，版本、页码、来源与限制一同显示。

## 接入与验收

通用分类与阶段资料矩阵见[通用框架说明](整理后的知识库/农用拖拉机知识库/通用框架说明.md)及`通用框架.json`。该框架维护系统、性能、表现、问诊与现有编号段的关联，不新增维修来源或扩大机型范围；原关联条目删除或正文改变时同步核对阶段及文字依据。新条目按实际证据建立关联，缺少的正常基准、检测条件或恢复验收保留待补，不把维护/故障数量或阶段线索当性能覆盖率。

从仓库根目录执行：

```bash
python3 知识库/工具/校验索引.py
# 新外链PDF尚在研究目录时，额外核验取得的文件：
python3 知识库/工具/校验索引.py --external-pdf SRC-资料编号=/tmp/原件.pdf
npm test
npm run build:server
```

校验工具使用Python标准库；PDF页数需`pdfinfo`（Poppler）或PyMuPDF之一，缺少时明确失败。工具不会下载原件或修改索引；外链旧资料未传临时PDF时明确标记本次未重复核验远端。

检查来源哈希、字节数、页数、唯一编号、源引用、标题定位、证据页范围和类型。测试确认每个条目可按记录的型号检索，未知/冲突型号不会套用；已填写的类型、品牌或完整型号与问题中的明确机型冲突时，停止召回并要求用户确认咨询对象。资料编号、URL及文件引用不作为实车身份；同册多型号范围仍逐条检查覆盖，不据此推定机型等价。重启服务后检查健康计数与真实机型问答，确认编号、版本、页码和边界出现在答案中。外部模型未配置时本地资料回答可验证；不据此声称外部模型或网站部署已验证。

最后保存用户授权范围内的资料、索引、文档和必要代码到GitHub；不提交临时研究文件或密钥。后续新增重复本流程，维护历史版本和未解决缺口。

## 通识资料参与问答（2026-10-17）

用户要求全部现有条目参与，通识按原有编号、主题和唯一Markdown正文接入同一检索快照。`docs/tractor-knowledge/`的两批索引继续保存原定位与 `diagnostic_evidence=false`；不把原创或模型辅助通识伪造为手册来源，不向维修用sources、entries或机型零件导航重复登记。

### 角色旁路文件与人工核对队列（2026-10-22）

`entries.jsonl` 有字节锁定的基线测试，因此 `roles`/`role_basis`/`risk_level`/`risk_basis` 改存于同目录 `entry-roles.jsonl`（每行 `entry_id` 加上述字段，不得与 `entries.jsonl` 重复填写）。`校验索引.py` 加载时并入条目，按同一规则校验，`原文标记` 仍逐项核对正文字段标签（`ROLE_MARKERS`）。正文无字段标签的可标注条目列入 `role-review-queue.jsonl`（`status: pending`），由人工核对后以 `人工核对` 依据写入旁路文件并移出队列。未标注不表示没有该角色。

### 人工核对队列的 AI 建议（2026-10-22）

`scripts/role-suggester-deepseek.mjs` 可为 `role-review-queue.jsonl` 中尚无建议的行写入 `ai_suggestion`：`label`（`roles`/`none`）、`roles`（按规范顺序）、`evidence`（每个角色一段正文逐字引文，脚本校验引文确实出现在正文中，否则丢弃该角色）、可选 `risk_level`/`risk_evidence`、`confidence`、`model`、`suggested_at`、`basis`。AI 建议只供人工参考：`status` 保持 `pending`，不得把 AI 建议直接写入 `entry-roles.jsonl`；人工确认后仍以 `人工核对` 依据写入旁路文件并移出队列。密钥只读环境变量 `DEEPSEEK_API_KEY`。
